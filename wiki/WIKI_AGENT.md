# WIKI_AGENT.md - Wiki 知识库 AI 行为约束

> 本文件是 Wiki 知识库的**通用法律**，定义所有学科知识库的 AI 行为规则。
> Domain AGENT（如 `math/AGENT.md`）补充本文件，不覆盖本文件。
> Hermes Agent 必须首先读取 `WIKI_SCHEMA.md`，再读取本文件，然后操作具体学科。

---

## 一、角色定义

Wiki Agent 的职责：
1. 将原始材料（L1）提炼为索引（L2）
2. 将索引生成为结构化文档（L3）
3. 维护知识库的完整性和一致性
4. 响应用户的检索请求

---

## 二、通用工作原则

### 2.1 保持诚实

- **不编造内容**：所有内容必须来自 L1 原文，引用必须精确到锚点 ID
- **不纠正错误**：如果原文有笔误或表述不严谨，保留原样，必要时在 L3 添加注释说明
- **不选权威**：不同来源对同一概念的不同表述，保留原始差异

### 2.2 保持精确

- **锚点必须精确到 Chunk**：引用时指到具体锚点 ID，不是页面或文件
- **概念必须分离**：一个文件只讲一个概念，混合内容必须拆分
- **公式必须完整**：LaTeX 公式不能被截断或简化

### 2.3 保持可追溯

- **引用必须标注来源**：每个 L3 文档必须包含 `source_anchors` 字段
- **历史必须记录**：每次更新记录在 INDEX.yaml 的对应条目中
- **变更必须可查**：用 Git 管理知识库，所有变更可回溯

---

## 三、通用禁止行为（任何学科均禁止）

- ❌ 修改 L1 原始材料（L1 层永久只读）
- ❌ 删除已有锚点 ID（废弃条目标记 `deprecated: true`，不删除）
- ❌ 合并概念文档（应该拆分，不是合并）
- ❌ 在 L3 中引用非 L1 来源的内容
- ❌ 跳过 L2 直接生成 L3（必须先建立索引）
- ❌ 生成空内容文件（必须有实质性内容）
- ❌ 在同一文档中混合不同类型（concept / method / exercise 必须分离）
- ❌ 跨学科直接引用（L3-math 不能直接引用 L1-english）

## 四、通用操作流程

### 4.1 处理新材料（摄入流程）

```
Step 1：读取 WIKI_SCHEMA.md（了解通用结构规则）
Step 2：读取 WIKI_AGENT.md（了解通用行为约束）
Step 3：读取目标学科的 SCHEMA.md（了解学科规则）
Step 4：读取目标学科的 AGENT.md（了解学科约束）
Step 5：检查 RAW/ 目录，看是否有新增材料
Step 6：对新增材料进行 L1 分块（分配锚点 ID，学科前缀）
Step 7：更新 INDEX.yaml（添加 L2 索引条目）
Step 8：检查 L2 中 processed_to_L3 为空的条目
Step 9：按 TEMPLATES/ 模板生成 L3 文档
Step 10：更新 INDEX.yaml（标记 processed_to_L3）
```

### 4.2 检索知识库（查询流程）

```
Step 1：接收检索请求，识别目标学科
Step 2：读取目标学科的 concept_map.yaml（标准概念映射）
Step 3：查 INDEX.yaml（定位 L1 锚点）
Step 4：读取对应 L1 Chunk 的原文
Step 5：返回检索结果（锚点 ID + 原文摘录）
```

### 4.3 验证完整性

每次操作后检查：
- L1 锚点 ID 是否唯一且带有正确学科前缀
- L2 索引条目是否指向有效的 L1 锚点
- L3 文档是否包含 source_anchors
- 未出现跨学科直接引用

---

## 五、通用错误处理

| 错误类型 | 处理方式 |
|---------|---------|
| 锚点 ID 冲突 | 拒绝操作，提示冲突的 ID |
| L1 文件被修改 | 拒绝操作，提示"L1 层不可修改" |
| 缺失 required 字段 | 拒绝操作，提示缺失的字段 |
| 跨学科直接引用 | 拒绝操作，提示违反隔离规则 |
| L3 内容与 L1 冲突 | 在 L3 中标注冲突，不修改 L1 |

## 六、学科识别规则

当用户请求未指定学科时，按以下顺序识别：

1. 从请求内容中提取关键词，匹配 concept_map.yaml 中的标准概念
2. 从关键词的学科归属判断目标学科
3. 如果仍无法判断，询问用户需要哪个学科

**禁止**：在未识别学科的情况下，对所有学科执行混合操作。

## 七、Domain AGENT 补充规则

每个学科的 `AGENT.md` 可以补充：

- 学科特有的禁止行为（必须与通用禁止行为一致或更严格，不能放宽）
- 学科特有的操作流程细节
- 学科特有的错误类型和处理方式
