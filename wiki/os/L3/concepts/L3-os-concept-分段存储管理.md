# 分段存储管理

## 形式化定义

> 引用自 RAW-os-3内存管理-3.1.4：

**分段**是将程序按逻辑划分为若干个段（如代码段、数据段、栈段等），每个段有独立的段名和长度。通过**段表**实现逻辑地址（段号+段内地址）到物理地址的映射。

## 直观解释

分段是按程序的"自然结构"来划分内存。像一本书分为前言、正文、附录等章节，每个章节独立编号。分段的好处是段与段之间可以独立保护和共享。

## 核心要点

### 1. 分页 vs 分段

| 比较维度 | 分页 | 分段 |
|----------|------|------|
| **目的** | 提高内存利用率（消除外部碎片） | 满足用户编程和共享保护的需要 |
| **划分方式** | 系统决定，大小固定 | 用户决定，大小可变 |
| **地址空间** | 一维（页号+偏移量） | 二维（段号+段内地址） |
| **透明性** | 对用户透明（用户不可见） | 对用户可见 |
| **共享保护** | 难以实现 | 易于实现段的共享与保护 |
| **碎片** | 无外部碎片，有内部碎片 | 无内部碎片，有外部碎片 |

### 2. 地址变换

```
逻辑地址 → [段号 | 段内地址]
               ↓
         查询段表 → 段长 + 段基址
               ↓
         判断段内地址 < 段长 → 不越界
               ↓
物理地址 = 段基址 + 段内地址
```

### 3. 段的共享与保护

| 功能 | 实现方式 |
|------|----------|
| **段的共享** | 两个作业的段表中相应表项指向被共享的段的同一物理副本 |
| **段的保护** | 存储控制保护 + 地址越界保护（段内地址 < 段长） |

### 4. 段页式存储管理

**段页式** = 分段 + 分页的组合：
1. 先将程序分段（按逻辑），每段再分页（按固定大小）
2. 地址结构：段号 + 段内页号 + 页内偏移量
3. 需要段表和页表两级映射

| 特点 | 说明 |
|------|------|
| 优点 | 兼具分段（逻辑清晰、共享保护）和分页（消除外部碎片）的优点 |
| 缺点 | 两次映射，时间开销大 |

## 常见考法

### 考法1：分页与分段的选择
**题目**：以下哪种存储管理方式有利于实现段的共享与保护？

A. 分页 B. 分段 C. 固定分区 D. 动态分区

**解析**：分段存储管理按逻辑划分，每个段有独立的意义，便于实现共享与保护。

**答案**：B

### 考法2：段页式地址转换
**题目**：段页式存储管理中，逻辑地址转换为物理地址需要访问几次内存？

**解析**：至少3次：第1次查段表（获得页表起始地址），第2次查页表（获得物理页框号），第3次访问目标物理内存地址。

## 注意事项

1. 分段是**用户可见**的，分页是**用户透明**的
2. 段页式需要2次查表（段表+页表）才能获得物理地址
3. 分段管理产生外部碎片，分页管理产生内部碎片
