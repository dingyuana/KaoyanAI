# 系统调用

## 形式化定义

> 引用自 RAW-os-1计算机系统概述-1.3：

**系统调用**（又称广义指令）是操作系统对应用程序和程序员提供的接口。当应用程序需要请求系统服务（如设备管理、文件操作、进程控制）时，通过触发 Trap（陷入/访管指令）进入核心态，由操作系统内核处理。

## 直观解释

系统调用是用户程序"请求"操作系统帮忙做事的通道。用户程序不能直接操作硬件（如读写磁盘、分配内存），必须通过系统调用请操作系统内核代为执行。就像你去餐厅不能直接进厨房炒菜，必须通过服务员（系统调用）下单。

## 核心要点

### 1. 系统调用的过程

```
应用程序 → 传参 → 陷入指令(Trap) → 内核处理 → 返回应用程序
                    (用户态)          (核心态)
```

**关键**：陷入指令（访管指令）的执行在用户态，系统调用的处理在核心态。

### 2. 系统调用分类

| 类型 | 功能 |
|------|------|
| 设备管理 | 完成设备的请求或释放、设备启动 |
| 文件管理 | 完成文件的读、写、创建、删除 |
| 进程控制 | 完成进程的创建、撤销、阻塞、唤醒 |
| 进程通信 | 完成进程之间的信息传递或信号传递 |
| 内存管理 | 完成内存的分配、回收、获取作业占用内存区大小及始址 |

### 3. 系统调用 vs 库函数

| 区别 | 系统调用 | 库函数 |
|------|---------|--------|
| 运行状态 | 用户态→核心态 | 用户态 |
| 实现机制 | 通过软中断（Trap） | 直接调用 |
| 开销 | 较大（需状态切换） | 较小 |

### 4. 系统调用 vs 一般过程调用

1. **运行状态不同**：系统调用涉及用户态→核心态切换；一般过程调用在同一状态
2. **软中断进入机制**：系统调用通过软中断机制；一般过程调用直接转向
3. **返回及重新调度**：系统调用完成后需重新调度所有进程；一般过程调用直接返回

## 常见考法

### 考法1：系统调用触发时机
**题目**：下列哪个操作必然触发系统调用？

A. 计算两数之和 B. 调用 printf C. 从键盘读入数据 D. 赋值操作

**解析**：scanf/printf涉及I/O操作，需要通过系统调用请求操作系统服务，触发Trap指令从用户态切换到核心态。A、D是普通运算，B（printf虽然是库函数，底层会调用系统调用write）。

**答案**：C（严格来说B的底层也会触发系统调用，但直接看：从键盘读入必然需要系统调用）

### 考法2：系统调用执行状态
**题目**：系统调用的调用和执行分别处于什么状态？

**解析**：系统调用的调用（通过访管指令）发生在用户态，系统调用的执行（内核处理程序）发生在核心态。

## 注意事项

1. 系统调用 = 广义指令，但位于用户态的程序不能执行特权指令
2. 访管/Trap指令是**非特权指令**，可在用户态执行
3. scanf()是C库函数，其内部会触发系统调用read()
