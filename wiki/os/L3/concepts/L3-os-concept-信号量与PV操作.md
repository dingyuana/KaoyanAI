# 信号量与PV操作

## 形式化定义

> 引用自 RAW-os-2进程与线程-PV操作定义：

**信号量（Semaphore）** 是一个整型变量，用于表示系统中可用资源的数量。
**P操作（Wait）**：信号量值S减1，若S<0则进程阻塞。
**V操作（Signal）**：信号量值S加1，若S≤0则唤醒一个阻塞进程。

## 直观解释

信号量就像一个"资源计数器"：
- **P操作** = 申请资源：资源数减1，如果没有资源了（S<0），就排队等待
- **V操作** = 释放资源：资源数加1，如果有人在等（S≤0），叫醒一个排队的人

## 核心要点

### 1. PV操作定义

| 操作 | 语义 | 效果 |
|------|------|------|
| **P(S)** | S = S - 1 | 若S≥0，进程继续；若S<0，进程阻塞 |
| **V(S)** | S = S + 1 | 若S≤0，唤醒一个阻塞进程；若S>0，继续 |

### 2. 信号量分类

| 类型 | 取值范围 | 用途 |
|------|----------|------|
| **整型信号量** | 非负整数 | 基础资源计数 |
| **记录型信号量** | 可负（表示等待进程数） | 常用方式，记录等待队列 |
| **二值信号量** | 0或1 | 互斥锁，用于实现互斥 |

### 3. PV操作实现同步与互斥

#### 实现互斥
```
mutex = 1; // 互斥信号量
P(mutex);
访问临界资源;
V(mutex);
```

#### 实现同步
```
sync = 0; // 同步信号量
// 在前操作之后加V(sync)
// 在后操作之前加P(sync)
```

**核心原则**：
- 互斥：P和V成对出现，夹住临界区
- 同步：在前操作后面V，在后操作前面P

### 4. 信号量应用场景

| 场景 | 信号量初值 | 说明 |
|------|-----------|------|
| 互斥访问 | 1 | 只有1个资源 |
| 有限资源 | N（资源数量） | 有N个同类资源 |
| 同步 | 0 | 前驱后继关系 |

## 常见考法

### 考法1：信号量值的意义
**题目**：若信号量S的初值为3，当前值为-2，表示什么？

**解析**：S初值3表示有3个可用资源。当前值为-2，说明有|S|=2个进程在等待。总共3+2=5个进程试图访问过该资源。

### 考法2：PV操作顺序
**题目**：在实现进程互斥时，PV操作必须怎样？

**解析**：P操作和V操作必须**成对出现**。缺少P操作不能保证互斥访问；缺少V操作会导致临界资源永远得不到释放、等待进程永远得不到唤醒。

## 注意事项

1. PV操作是**低级通信方式**，是**原子操作**（不可中断）
2. 互斥时P和V**必须成对出现**
3. 同步时，在前操作之后V，在后操作之前P
4. 多个同步和互斥混合时，要注意P操作的先后顺序（通常先同步后互斥）
