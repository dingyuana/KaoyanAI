# 死锁

## 形式化定义

> 引用自 RAW-os-2进程与线程-2.4：

**死锁**是多个进程因竞争资源而造成的一种互相等待，若无外力作用，这些进程都无法向前推进。死锁的充分条件：资源分配图中每种资源只有一个，又出现了环路。

## 直观解释

死锁就像两个人在狭窄的过道相遇：A要先走需要B让路，B要先走需要A让路，两人都不让步，结果都走不了。每个进程都持有对方需要的资源，谁都不释放。

## 核心要点

### 1. 死锁产生的必要条件

| 条件 | 说明 |
|------|------|
| **互斥条件** | 多个线程不能同时使用同一个资源 |
| **不剥夺条件** | 进程在自己使用完资源前不能被其他进程抢占 |
| **请求并保持条件** | 进程已持有资源，申请新资源时被阻塞但不释放已有资源 |
| **循环等待条件** | 进程获取资源的顺序构成了环形链 |

**四个条件必须同时满足才会产生死锁。**

### 2. 死锁 vs 饥饿

| 区别 | 死锁 | 饥饿 |
|------|------|------|
| 涉及进程数 | ≥2个 | 可以只有1个 |
| 进程状态 | 必定是阻塞态 | 可以是就绪态 |
| 是否一定系统死锁 | 是 | 不一定 |

### 3. 死锁处理策略

| 策略 | 方法 | 特点 |
|------|------|------|
| **预防** | 破坏四大必要条件之一 | 简单但资源利用率低 |
| **避免** | 银行家算法 | 动态判断，较灵活 |
| **检测** | 资源分配图化简 | 允许死锁，定期检测 |
| **解除** | 撤销进程/剥夺资源 | 系统开销大 |

### 4. 死锁预防方法

| 预防方法 | 破坏的条件 | 具体做法 |
|----------|-----------|----------|
| 破坏互斥条件 | 互斥条件 | 将独占设备改造为共享设备（如SPOOLing） |
| 破坏不剥夺条件 | 不剥夺条件 | 进程请求新资源失败时释放已有资源 |
| 破坏请求并保持条件 | 请求并保持条件 | 进程一次性申请全部所需资源 |
| 破坏循环等待条件 | 循环等待条件 | 对所有资源类型排序，按序申请 |

## 常见考法

### 考法1：判断是否死锁
**题目**：系统中有3个进程和4个同类资源，每个进程最多需要2个资源，该系统是否会死锁？

**解析**：每个进程需要最多2个资源。最坏情况：每个进程分到1个资源（共3个），还剩1个资源。无论哪个进程获得第2个资源，都能运行完成后释放。所以不会死锁。

**答案**：不会死锁

### 考法2：四大必要条件
**题目**：下列哪一个不是死锁产生的必要条件？

A. 互斥条件 B. 不剥夺条件 C. 请求并保持条件 D. 资源有序分配

**解析**：资源有序分配是破坏循环等待条件的预防方法，不是必要条件。四个必要条件：互斥、不剥夺、请求并保持、循环等待。

**答案**：D

## 注意事项

1. 只有对**不可剥夺资源**的竞争才可能产生死锁
2. 死锁预防 = 破坏四大条件之一
3. 死锁避免 = 银行家算法，是最常用的避免方法
4. 处于饥饿状态的进程可以是**就绪进程**，而死锁进程必定是**阻塞进程**
