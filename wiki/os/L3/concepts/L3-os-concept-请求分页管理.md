# 请求分页管理

## 形式化定义

> 引用自 RAW-os-3内存管理-3.2.2：

**请求分页管理**是在基本分页管理基础上增加了**请求调页**和**页面置换**功能的存储管理方式。只要求将当前一部分页面装入内存即可启动作业运行，当访问的页面不在内存时通过调页功能将其调入。

## 直观解释

请求分页就像"按需取书"：需要看哪一页内容，才去书架上找那一页来看，不看的页面就放回书架。内存就是"桌面"（放少量页面），磁盘就是"书架"（存所有页面）。

## 核心要点

### 1. 相比基本分页增加的功能

| 功能 | 说明 |
|------|------|
| **请求调页** | 将需要的页面从外存调入内存 |
| **页面置换** | 内存满时，将不用的页面换出到外存 |

### 2. 页表新增字段

| 字段 | 说明 |
|------|------|
| **状态位P** | 标识该页是否在内存中 |
| **访问字段A** | 记录最近被访问的次数或时间 |
| **修改位M** | 页面是否被修改（修改过的页面换出时要写回磁盘） |
| **外存地址L** | 该页在外存中的存放位置 |

### 3. 缺页中断

**缺页中断**属于内中断（故障）：
1. 进程访问某页时，状态位P=0（不在内存）
2. CPU检测到缺页，产生缺页中断
3. 操作系统从外存读入所需页面
4. 若内存已满，先执行页面置换算法
5. 更新页表，返回原指令重新执行

### 4. 页框分配

| 策略 | 说明 |
|------|------|
| **固定分配** | 每个进程分配固定数量的物理块 |
| **可变分配** | 根据缺页率动态调整物理块数量 |
| **全局置换** | 可从所有进程的物理块中置换 |
| **局部置换** | 只能置换自己进程的物理块 |

### 5. 抖动与工作集

| 概念 | 定义 | 原因 |
|------|------|------|
| **抖动（颠簸）** | 频繁的页面换入换出，CPU利用率急剧下降 | 分配给进程的物理块过少 |
| **工作集** | 进程当前一段时间内访问的页面集合 | 用于指导页框分配 |

## 常见考法

### 考法1：缺页中断的处理
**题目**：缺页中断属于哪种中断？发生缺页时，OS如何处理？

**解析**：缺页中断属于内中断（故障）。OS处理流程：
1. 保存CPU现场
2. 查找外存中该页的位置
3. 若内存有空闲页框，直接读入；否则执行页面置换
4. 修改页表（状态位P=1）
5. 恢复现场，重新执行被中断的指令

### 考法2：抖动的原因
**题目**：发生系统抖动的原因是？

**解析**：分配给进程的物理块数量**过少**，导致进程频繁缺页，页面不断换入换出，CPU大部分时间用于处理页面置换而非执行程序。

## 注意事项

1. 缺页发生在**用户态**，但缺页处理程序在**核心态**执行
2. 缺页中断处理后返回原指令**重新执行**（非下一条指令）
3. 工作集大小应小于分配给进程的物理块数，否则会发生抖动
