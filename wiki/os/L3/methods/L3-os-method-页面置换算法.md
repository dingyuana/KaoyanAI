# 页面置换算法

## 适用场景

当请求分页管理系统发生缺页中断且内存已满时，需要选择淘汰内存中的某个页面，用新页面替换之。页面置换算法的目标是使未来的缺页率最低。

## 算法总览

| 算法 | 淘汰页面 | 特点 |
|------|----------|------|
| **最佳置换（OPT）** | 以后永不使用或最远使用的 | 理论最优，无法实现 |
| **先进先出（FIFO）** | 内存中驻留最久的 | 实现简单，可能Belady异常 |
| **最近最久未使用（LRU）** | 最近最长时间未访问的 | 性能好，实现复杂 |
| **时钟置换（CLOCK）** | 访问位为0的 | FIFO和LRU的折中 |

## 方法步骤

### OPT（最佳置换算法）

**步骤**：
1. 当发生缺页且内存已满时
2. 检查内存中每个页面**未来**被访问的情况
3. 淘汰未来最久才被访问（或永不访问）的页面

**特点**：缺页率最低，但无法实现（无法预知未来访问序列），仅用于理论评价

### FIFO（先进先出置换算法）

**步骤**：
1. 维护页面进入内存的队列
2. 发生缺页时，淘汰队首页面
3. 新页面加入队尾

**特点**：
- 实现简单
- 可能发生**Belady异常**：分配的物理块增多，缺页次数反而增加

### LRU（最近最久未使用置换算法）

**步骤**：
1. 维护每个页面的最近访问时间
2. 发生缺页时，淘汰最近最久未使用的页面

**实现方式**：
- **计数器法**：为每个页面关联一个访问计数器
- **栈法**：使用栈记录页面访问顺序，最近访问的页面在栈顶

**特点**：性能好，但实现复杂（需要硬件支持）

### CLOCK（时钟置换算法）

**步骤**：
1. 将所有页面组织成循环队列
2. 使用**访问位**标记页面是否被访问过
3. 发生缺页时，从指针当前位置开始扫描：
   - 访问位=0 → 淘汰该页面
   - 访问位=1 → 置0，继续扫描
4. 若扫描一圈未找到 → 淘汰当前页面

**改进型CLOCK**：同时使用访问位和修改位：
| (访问位, 修改位) | 优先级 |
|------------------|--------|
| (0, 0) | 最优淘汰 |
| (0, 1) | 次优 |
| (1, 0) | 较差 |
| (1, 1) | 最差淘汰 |

## 示例

**问题**：页面访问序列为：7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1，物理块数为3。

**OPT置换**（仅展示前几次）：
```
7 → 缺页 [7]
0 → 缺页 [7, 0]
1 → 缺页 [7, 0, 1]
2 → 缺页，淘汰7 [2, 0, 1]  // 7未来最远才用
0 → 命中 [2, 0, 1]
...
```
OPT缺页率最低，作为其他算法的比较基准。

**FIFO置换**：
```
7 → 缺页 [7]
0 → 缺页 [7, 0]
1 → 缺页 [7, 0, 1]
2 → 缺页，淘汰7 [2, 0, 1]
0 → 命中 [2, 0, 1]
3 → 缺页，淘汰0 [2, 3, 1]
...
```

**LRU置换**：
```
7 → 缺页 [7]
0 → 缺页 [7, 0]
1 → 缺页 [7, 0, 1]
2 → 缺页，淘汰7 [2, 0, 1]  // 7最久未用
0 → 命中 [2, 0, 1]
3 → 缺页，淘汰1 [2, 0, 3]  // 1最久未用
...
```

## 注意事项

1. OPT无法实现，仅用作**性能评价基准**
2. FIFO可能发生**Belady异常**（块增多反而缺页增多）
3. LRU性能最好但实现成本高
4. CLOCK是FIFO和LRU的折中方案，实际系统中常用
5. 改进型CLOCK考虑页面是否被修改（修改过的页面换出需写回磁盘，代价大）

## 失效情况

- 当工作集大于物理块数时，任何算法都会产生频繁缺页（**抖动**）
- 根本解决方案：增加物理块数或减少运行程序数
