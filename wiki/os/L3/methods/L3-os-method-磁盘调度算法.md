# 磁盘调度算法

## 适用场景

当多个进程同时请求访问磁盘时，磁盘调度算法决定响应请求的顺序，以最小化**寻道时间**（磁盘访问最耗时的部分），提高磁盘访问性能。

## 算法总览

| 算法 | 策略 | 优点 | 缺点 |
|------|------|------|------|
| **FCFS** | 按请求顺序服务 | 公平简单 | 寻道时间长 |
| **SSTF** | 选最近磁道的请求 | 比FCFS好 | 可能饥饿 |
| **SCAN（电梯算法）** | 单向移动，到头折返 | 性能好，无饥饿 | 中间磁道响应频繁 |
| **C-SCAN（循环扫描）** | 单向移动，快速回零 | 各磁道响应均匀 | 平均寻道长 |

## 方法步骤

### 第一步：计算寻道时间

一次磁盘访问时间 = 寻道时间 + 旋转延迟 + 传输时间

**寻道时间** Ts = s + m × n（s为启动时间，m为每磁道移动时间，n为跨越磁道数）

调度算法的优化目标是减少**寻道距离**（即磁头移动的总磁道数）。

### 第二步：选择算法

#### FCFS（先来先服务）

按请求到达的顺序依次服务。简单但若请求分散则性能差。

#### SSTF（最短寻道时间优先）

每次选择离当前磁头最近的请求。贪心策略，但可能使远处的请求**饥饿**。

#### SCAN（扫描/电梯算法）

1. 磁头沿一个方向移动，响应路径上的所有请求
2. 到达该方向末端后反向移动
3. 类似电梯运行方式

#### C-SCAN（循环扫描算法）

1. 磁头只沿一个方向移动响应请求
2. 到达末端后**快速复位**到起始端
3. 复位途中不响应任何请求
4. 各磁道响应频率更均匀

## 示例

**问题**：请求序列：98, 183, 37, 122, 14, 124, 65, 67，磁头初始位置：53

**FCFS处理顺序**：
53 → 98(45) → 183(85) → 37(146) → 122(85) → 14(108) → 124(110) → 65(59) → 67(2)
总寻道距离：45+85+146+85+108+110+59+2 = **640**

**SSTF处理顺序**：
53 → 65(12) → 67(2) → 37(30) → 14(23) → 98(84) → 122(24) → 124(2) → 183(59)
总寻道距离：12+2+30+23+84+24+2+59 = **236**

**SCAN处理顺序**（假设朝磁道号减小方向）：
53 → 37(16) → 14(23) → 0(14) → 65(65) → 67(2) → 98(31) → 122(24) → 124(2) → 183(59)
总寻道距离：16+23+14+65+2+31+24+2+59 = **236**

**C-SCAN处理顺序**（假设朝磁道号增加方向）：
53 → 65(12) → 67(2) → 98(31) → 122(24) → 124(2) → 183(59) → 199(16) → 0(199) → 14(14) → 37(23)
总寻道距离：12+2+31+24+2+59+16+199+14+23 = **382**

## 注意事项

1. 磁盘调度的主要目标是优化**寻道时间**
2. SSTF虽然总寻道时间短，但会导致**饥饿**（远处请求可能永远不被服务）
3. SCAN算法无饥饿问题，但中间磁道相对"占便宜"
4. C-SCAN使各磁道响应频率更均匀

## 失效情况

- 现代磁盘控制器通常内置硬件调度（操作系统发出的顺序可能被控制器重新排序）
- 固态硬盘（SSD）无寻道时间，不需要磁盘调度算法（随机访问和顺序访问性能接近）
