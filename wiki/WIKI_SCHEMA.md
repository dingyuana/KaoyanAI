# WIKI_SCHEMA.md - Wiki 知识库通用规范

> 本文件是 Wiki 知识库的**总宪法**，定义所有学科知识库的通用结构与规则。
> MVP 阶段完成后，本文件不再发生结构性变更。
> 所有学科 Domain SCHEMA（如 `math/SCHEMA.md`）必须遵循本文件。

---

## 一、Wiki 定义

Wiki 是一个**分层知识库**，由多学科知识库组成，每个学科包含三层结构。

```
kaoyan/wiki/
├── WIKI_SCHEMA.md          # 本文件，总宪法
├── WIKI_AGENT.md           # 通用AI行为约束
│
├── {subject}/              # 学科目录（math / english / politics / ...）
│   ├── SCHEMA.md           # Domain宪法（本学科领域规则）
│   ├── AGENT.md            # Domain AI约束（本学科补充）
│   ├── INDEX.yaml          # L2 索引（学科内通用）
│   ├── RAW/                # L1 原始材料
│   ├── L3/                 # L3 最终文档
│   │   ├── concepts/       # 概念文档
│   │   ├── methods/         # 方法文档
│   │   └── exercises/       # 习题文档
│   ├── TEMPLATES/          # 本学科文件模板
│   └── _meta/              # 本学科元数据
│       └── concept_map.yaml  # 标准概念词表
│
└── _shared/                # 跨学科共享资源（可选）
    └── ...
```

**规则**：学科目录 `{subject}` 使用小写英文（math / english / politics）。

---

## 二、三层结构（永久不变）

### 2.1 各层职责

| 层级 | 名称 | 职责 | 性质 |
|------|------|------|------|
| L1 | Raw | 原始材料，永久只读 | 不可修改、不可删除 |
| L2 | Index | L1 的索引目录，描述特征和关系 | 可追加、不可删除已有条目 |
| L3 | Generated | 最终应用文档，一概念一文件 | 可修改、可扩展 |

### 2.2 层间关系

```
L1（原文） → L2（索引） → L3（应用文档）
```

- **允许**：L3 引用 L1（通过锚点ID）
- **允许**：L3 引用 L2（同层引用）
- **禁止**：L1 引用 L2/L3（下层不可引用上层）
- **禁止**：跨学科直接引用（math 的 L3 不能直接引用 english 的 L1）

## 三、锚点 ID 体系（永久不变）

### 3.1 格式定义

| 层级 | 格式 | 示例 |
|------|------|------|
| L1 | `RAW-{subject}-{来源}-P{页码}-C{序号}` | `RAW-math-同济高数上-P023-C07` |
| L2 | `INDEX-{subject}-{类型}-{概念标识}` | `INDEX-math-concept-极限定义` |
| L3 | `L3-{subject}-{类型}-{文件名}` | `L3-math-concept-极限的概念与性质` |

### 3.2 永久性规则

- ✅ 锚点 ID 一旦分配，**永不改变**
- ✅ 锚点 ID 一旦分配，**永不重用**
- ✅ L1 中的锚点 ID **永不删除**（即使原文被废弃，标记为 `deprecated: true`，不删除）
- ✅ L2 中的锚点 ID **永不删除**
- ❌ 禁止在任何情况下覆盖已有锚点 ID

### 3.3 学科前缀

每个锚点 ID 必须以学科前缀开头，实现跨学科隔离：

| 学科 | 前缀 | 示例 |
|------|------|------|
| 数学 | `math` | `RAW-math-同济高数上-P001-C01` |
| 英语 | `english` | `RAW-english-考研词汇-P001-C01` |
| 政治 | `politics` | `RAW-politics-马原-P001-C01` |

## 四、多源管理原则（永久不变）

### 4.1 冲突处理规则

| 情况 | 处理方式 |
|------|---------|
| 表述不同，含义一致 | L3 合并呈现，多源对照，不选"权威版本" |
| 讲解侧重不同 | L2 新增 `perspective` 字段，L3 按视角分组 |
| 存在矛盾 | L1 保留冲突原文，L3 显式标注，不擅自裁决 |

### 4.2 核心原则

- **不隐藏冲突**：原始差异必须可见
- **不选权威**：不同来源享有平等地位
- **可添加建议**：可标注"考研适用性"等实践性建议
- **大纲为准**：以官方考试大纲为最终准

## 五、Domain SCHEMA 规范

每个学科目录下的 `SCHEMA.md` 必须定义：

### 必须定义

1. **学科范围** — 本学科包含哪些知识领域
2. **页面类型** — 本学科有哪些类型的文档（concept / method / exercise 或其他）
3. **分块原则** — L1 分块的具体规则
4. **命名规范** — 本学科 RAW 文件的命名格式

### 可以定义

5. **概念分类体系** — 本学科的章节/模块划分
6. **学科特色规则** — 本学科特有的处理方式（如数学的 LaTeX 格式）
7. **与其他学科的关联** — 跨学科概念映射（不实现引用，只记录关联）

### 不得定义

- ❌ 不得定义三层结构的层级数（L1/L2/L3 数量固定）
- ❌ 不得定义锚点 ID 格式（格式固定，前缀除外）
- ❌ 不得定义多源冲突处理原则（全局统一）
- ❌ 不得定义层间关系（全局统一）

---

## 六、Domain AGENT 规范

每个学科目录下的 `AGENT.md` 必须定义：

### 必须定义

1. **学科角色** — 本学科 AI 的职责描述
2. **学科禁止行为** — 本学科特有的禁止操作

### 可以定义

3. **学科操作流程** — 本学科特有的工作流细节
4. **学科错误处理** — 本学科特有的错误类型和处理方式

### 不得定义

- ❌ 不得定义通用行为（通用行为在 `WIKI_AGENT.md` 中定义）
- ❌ 不得覆盖全局禁止行为

---

## 七、可扩展性规则

### 7.1 允许扩展

- ✅ 新增学科目录（如 `physics/`、`chemistry/`）
- ✅ 新增 L3 子目录（如 L3 下新增 `summary/` 考前速记）
- ✅ 新增 `_meta/` 元数据文件
- ✅ Domain SCHEMA 演进（补充学科规则，不改变结构）

### 7.2 禁止扩展（基座不变）

- ❌ 改变 L1/L2/L3 三层数量
- ❌ 改变锚点 ID 格式（除学科前缀外）
- ❌ 改变多源冲突处理原则
- ❌ 删除已有锚点 ID
- ❌ 修改 L1 原始材料内容
