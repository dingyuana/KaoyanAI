# 原码、反码、补码与定点数表示

## 形式化定义

> 引用自 [[RAW-arch-2数据表示和运算-原码补码]]：

- **真值**：带符号的数值，如 +5
- **机器数**：符号数值化的表示，如 05（0表示正，1表示负）
- **原码**：符号位+数值绝对值，如 +1 = 00000001，-1 = 10000001
- **反码**：正数=原码，负数=符号位不变，数值位取反
- **补码**：正数=原码，负数=反码+1（即2^n - |负数|）

**补码重要法则**：(二进制的值取反+1) + (原来的值) = 0

**表示范围**（补码，n位）：
- 有符号数范围：$-2^{n-1} \sim 2^{n-1}-1$
- 无符号数范围：$0 \sim 2^n-1$

## 直观解释

计算机用二进制表示正负数，原码最直观（符号位+数值），但计算复杂（1+(-1)≠0）。补码解决了这个问题，让符号位也参与运算，且0的表示唯一。补码的优点是可以用加法器统一处理加减法。

## 核心要点

1. **8位补码整数范围**：-128~127（负数比正数多一个，因为0只占正数区）
2. **补码优点**：0的表示唯一、运算规则简单、符号位和数值位一起参与运算
3. **补码获取**：负数补码 = 原码符号位不变，数值位取反+1
4. **补码求值**：对补码再求补码得到原码
5. **无符号数**：所有位都是数值位，用于表示主存地址

## 常见考法

### 考法1：补码表示范围
**题目**：16位补码能表示的最小负数是多少？
**答案**：$-2^{15} = -32768$

### 考法2：原码1+(-1)出错的原因
**答案**：若用原码，1=00000001，-1=10000001，相加得10000010，结果非0。补码则1+(-1)=00000001+11111111=00000000（高位丢弃），结果为0。

## 注意事项

1. 补码的符号位可以和数值位一起参与运算
2. 正数的原、反、补码都相同
3. short（有符号16位）范围：-32768~32767；unsigned short范围：0~65535
4. 原码不能表示负数运算，补码可以
