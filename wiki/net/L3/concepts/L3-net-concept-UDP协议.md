# UDP协议

## 形式化定义

> 引用自 [[RAW-net-5传输层-5.2 UDP协议]]：

UDP（User Datagram Protocol）用户数据报协议，是传输层的无连接协议，提供不可靠的、尽最大努力交付的传输服务。UDP = IP的数据报服务 + （复用、分用、差错检测）。

## UDP特点

| 特性 | 说明 |
|------|------|
| **无连接** | 发送数据前不需要建立连接 |
| **尽最大努力交付** | 不保证可靠交付 |
| **无拥塞控制** | 有利于实时应用（视频、语音） |
| **首部开销小** | 仅8字节 |
| **面向报文** | 报文是UDP数据报处理的最小单位 |

## UDP首部格式

| 字段 | 长度(字节) | 说明 |
|------|-----------|------|
| 源端口 | 2B | 可选，需要对方回信时使用 |
| 目的端口 | 2B | 终点交付报文时必须使用 |
| 长度 | 2B | UDP数据报总长度（首部+数据），最小值为8 |
| 校验和 | 2B | 检测UDP在传输中是否出错 |

## UDP校验和

### 伪首部
UDP在计算校验和时，要在UDP用户数据报之前增加12字节的伪首部：

| 字段 | 长度(字节) | 说明 |
|------|-----------|------|
| 源IP地址 | 4B | 与IP数据报相同 |
| 目的IP地址 | 4B | 与IP数据报相同 |
| 全零 | 1B | 固定为0 |
| 协议 | 1B | UDP协议的协议字段值是17 |
| UDP长度 | 2B | UDP用户数据报长度 |

### 校验过程
1. 校验和字段置0
2. 将伪首部和UDP数据报看成16位为单位，依次进行二进制**反码求和**
3. 将求和结果的反码写入校验和字段

## UDP基于端口的分用
1. 接收方IP层收到UDP数据报后，根据首部中的目的端口交付给上层应用进程
2. 若目的端口号不正确（不存在对应应用进程），则丢弃该报文
3. 由ICMP发送"端口不可达"差错报文给发送方

## 注意事项

1. UDP首部开销小（8B），TCP首部20B
2. 伪首部不向下传送也不向上递交，只用于计算校验和
3. UDP校验可丢弃也可交付（附错误报告）
4. 典型UDP应用：DNS（53）、TFTP（69）、SNMP（161）
