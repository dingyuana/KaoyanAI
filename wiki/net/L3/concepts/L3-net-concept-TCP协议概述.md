# TCP协议概述与报文段

## 形式化定义

> 引用自 [[RAW-net-5传输层-5.3 TCP协议]]：

TCP（Transmission Control Protocol）传输控制协议，是传输层的面向连接、可靠传输协议。TCP提供全双工通信，面向字节流，保证数据无差错、不丢失、不重复且按序到达。

## TCP特点

| 特性 | 说明 |
|------|------|
| **面向连接** | TCP是面向连接的传输层协议 |
| **虚电路** | TCP连接是一条逻辑连接，不是真正的物理连接 |
| **点对点** | 每条TCP连接只能有两个端点 |
| **可靠交付** | 保证数据无差错、不丢失、不重复、按序到达 |
| **全双工通信** | 双方可同时发送和接收数据 |
| **面向字节流** | TCP把应用程序交下来的数据视为一连串无结构的字节流 |
| **连接端点** | TCP连接的端点叫套接字（Socket）= (IP地址 : 端口号) |

### TCP连接标识
TCP连接 = {socket1, socket2} = {(IP1:port1), (IP2:port2)}

## TCP报文段首部格式

| 字段 | 长度(bit) | 说明 |
|------|----------|------|
| 源端口 | 16 | 发送方端口号 |
| 目的端口 | 16 | 接收方端口号 |
| 序号 | 32 | 报文段所发送数据第一个字节的序号 |
| 确认号 | 32 | 期望收到下一个报文段第一个数据字节的序号 |
| 数据偏移 | 4 | TCP首部长度（以4B为单位），最小20B |
| 保留 | 6 | 保留为今后使用 |
| 紧急位URG | 1 | URG=1表示报文段中有紧急数据 |
| 确认位ACK | 1 | ACK=1时确认号才有效 |
| 推送位PSH | 1 | 实际很少使用 |
| 复位位RST | 1 | TCP连接出现差错，需释放连接重新建立 |
| 同步位SYN | 1 | 在连接建立时用来同步序号 |
| 终止位FIN | 1 | 用来释放一个连接 |
| 窗口 | 16 | 接收方让发送方设置发送窗口的依据 |
| 校验和 | 16 | 校验首部和数据部分（需要伪首部） |
| 紧急指针 | 16 | URG=1时表示紧急数据的字节数 |
| 选项 | 可变 | MSS、扩大窗口、时间戳等 |

### TCP首部最小字节
- TCP首部最小为 **20字节**
- 加上选项后最多可达 **60字节**

## 发送缓存与接收缓存

| 缓存 | 内容 |
|------|------|
| **发送缓存** | 准备发送的数据 + 已发送但未收到确认的数据 |
| **接收缓存** | 按序到达但尚未被读取的数据 + 不按序到达的数据 |

## 注意事项

1. TCP是面向连接的，UDP是无连接的
2. TCP提供可靠交付，UDP提供尽最大努力交付
3. TCP面向字节流，UDP面向报文
4. TCP首部20B，UDP首部8B
5. TCP序号建立在字节流之上，不是报文段之上
