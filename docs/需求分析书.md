# 需求分析书

> **项目名称：** Kaoyan Wiki（考研智能学习助手）
> **版本：** 2.0.0
> **状态：** 正式发布

---

## 一、引言

### 1.1 目的

本文档旨在系统、完整地定义 **Kaoyan Wiki 考研智能学习助手** 的功能需求与非功能需求，作为后续系统设计、开发、测试与验收的统一基准。文档面向开发团队、测试团队、产品经理及项目相关方。

### 1.2 范围

Kaoyan Wiki 是一个 AI 驱动的考研全周期智能学习助手，核心围绕 LLM Wiki 知识库基座，提供学习诊断、个性化规划、AI 辅导、错题管理、阶段检测、智能信息中枢与择校辅助等功能。初期 MVP 以数学二（高等数学 + 线性代数）为知识起点，后续扩展至数学一/三、英语、政治、计算机等专业课。

### 1.3 术语与缩写

| 术语 | 说明 |
|------|------|
| **LLM Wiki** | Karpathy 提出的知识管理思想，将 LLM 作为知识编译器，将原始资料编译为结构化、可进化的 Wiki 知识库 |
| **主干+分支** | 知识库构建架构：一套权威主干课程建立知识基线，其他课程以补充视角接入 |
| **AGENTS.md** | LLM 编译与维护 Wiki 的指令手册 |
| **RAG** | 检索增强生成（Retrieval-Augmented Generation），用于 AI 辅导的知识检索与回答生成 |
| **知识复利** | 系统主动发现知识缺口，经内容团队审核后沉淀回 Wiki，知识库随使用持续增值 |
| **引导式辅导** | AI 先给提示引导独立思考，学生确认后再展示完整解析，避免直接给出答案 |
| **知识缺口** | AI 辅导中用户提问无法命中 Wiki 知识库的高频知识点，系统自动统计并提交内容团队 |
| **智能信息中枢** | 主动采集研招网及院校招生信息，编译为结构化 Wiki 并个性化推送 |
| **P0 / P1** | 优先级：P0 为必须实现，P1 为重要但可稍后实现 |

## 二、总体描述

### 2.1 产品定位

一款 AI 驱动的考研全周期智能助手，以结构化、可进化的 LLM Wiki 知识库为基座，深度融合备考知识学习与招生信息服务，帮助考研学生实现从信息获取到科学决策的全流程闭环。

### 2.2 用户角色

| 角色 | 描述 |
|------|------|
| **考生（学习者）** | 系统的核心用户，备考全国硕士研究生入学考试的学生。需要诊断、规划、答疑、错题管理、信息获取等。 |
| **内容管理员（教研）** | 负责审核 LLM 生成的 Wiki 内容、处理知识缺口列表、管理后台编译流水线，确保知识质量。 |
| **系统管理员** | 管理用户数据、系统配置、监控运行状态。 |

### 2.3 设计约束

- **技术栈假设**：后端 Python（FastAPI），前端 Next.js，向量数据库（如 Milvus/Qdrant），图数据库（如 Neo4j），LLM 接口支持国产大模型通配（通义千问、DeepSeek 等）。
- **知识库格式**：Markdown + LaTeX 公式，存储于 Git 仓库与向量数据库。
- **数据安全**：遵守《个人信息保护法》，学习数据与个人信息物理分离，传输加密。
- **AI 辅导原则**：默认采用引导式辅导，避免替学生思考，符合 AGENTS.md 规范。
- **知识库权限**：终端用户仅拥有只读权限，写入操作统一由内容管理员通过后台编译流水线完成。

## 三、功能需求

### 3.1 知识库基座（P0）

#### 3.1.1 知识库浏览与检索
- 系统应预置数学二（高等数学 + 线性代数）全量 Wiki 知识库，涵盖考纲所有核心知识点。
- 用户可通过章节目录树逐级浏览，也可通过关键词进行全文搜索。
- 每个知识点页面包含：概念定义、核心公式（LaTeX 格式）、名师精讲、经典例题、易错点警示、内容来源标注。
- 页面之间通过"前置知识"、"关联考点"、"同类辨析"等链接建立双向关联，至少 3 个关联链接。
- 后续科目扩展时，新科目知识库以相同标准编译后统一纳入。

#### 3.1.2 后台资料导入与编译
- **仅内容管理员**可在管理后台上传 PDF、Word、PPT、Markdown、视频字幕（.srt/.vtt）、音频转录文本等原始资料。
- 上传后系统应自动触发编译流水线，将资料转换为统一 Markdown 格式，保留公式（LaTeX）、表格和标题层级。
- 系统应基于 AGENTS.md 规范，将指定的主干课程资料编译为结构化 Wiki 页面。

#### 3.1.3 分支课程补充编译
- 当内容管理员导入新的名师课程时，系统应在 AGENTS.md 规则下，仅提取与主干有差异的口诀、例题、理解角度，以"补充视角"或"方法对比"形式轻量接入已有页面。
- 分支内容应标注教师来源与课程名称，不覆盖原有主干定义。

#### 3.1.4 知识图谱构建
- 系统应自动识别 Wiki 页面间的引用关系，构建知识点之间的前后置依赖、同类关联、易混辨析等关系图。
- 支持内容管理员在后台手动调整图谱节点和边。

#### 3.1.5 知识缺口检测（知识复利机制）
- 系统应自动统计 AI 辅导中用户提问无法命中 Wiki 知识库的高频知识点。
- 每周期（如每周）在管理后台生成"知识缺口列表"，按提问频次降序排列。
- 内容管理员可将缺口条目标记为"已忽略"或"加入编译队列"。
- 加入编译队列后，系统自动生成 Wiki 页面草稿，经内容管理员审核修订后发布。
- 终端用户完全无感知该机制，无任何主动上报入口，无任何触发入库的能力。

#### 3.1.6 大纲版本管理
- 系统应能导入新一年度的考试大纲 PDF，自动对比差异，更新受影响的 Wiki 页面，并记录修订日志。

### 3.2 学习诊断（P0）

#### 3.2.1 自适应诊断测试
- 首次使用时，系统应根据用户目标科目（初始为数学二）生成一套自适应诊断试题，覆盖各核心知识模块。
- 试题难度应根据用户答题情况动态调整。

#### 3.2.2 智能批改
- 系统应自动批改客观题（选择题、填空题），识别正确/错误。
- 对于主观题（计算题、证明题），应基于 LLM 进行步骤级批改，标记出错步骤。

#### 3.2.3 薄弱点归因
- 基于错题和错误步骤，系统应将错误归类为：概念不清、计算失误、审题偏差、方法错误等。
- 将薄弱点关联到具体的 Wiki 知识点页面，精确定位薄弱环节。

#### 3.2.4 诊断报告
- 每次诊断结束后，应生成一份诊断报告，包含：各模块得分、知识掌握概览、主要薄弱点、建议优先复习模块。

### 3.3 个性化学习规划（P0）

#### 3.3.1 初始计划生成
- 基于诊断结果、用户目标分数、考试日期、每日可用学习时间，系统应自动生成覆盖备考全周期的阶段学习计划。
- 计划应分解到"每日任务"粒度，任务与 Wiki 知识点页面或题库练习关联。

#### 3.3.2 动态调整
- 根据用户每日任务完成度、练习正确率、诊断结果变化，系统应自动调整后续计划：
  - 薄弱知识点自动增加复习频次与练习量；
  - 进度超前时推荐进阶内容或强化练习；
  - 进度严重滞后时发出提醒，并建议压缩非核心模块时间。

#### 3.3.3 任务提醒与推送
- 系统应支持在设定的学习时间前提醒用户当日任务。
- 支持通过站内通知或邮件提醒（MVP 阶段至少提供页面内提示）。

### 3.4 AI 辅导（P0）

#### 3.4.1 多模态题目输入
- 用户可通过文本输入、拍照上传或语音输入题目，系统应能识别印刷体、工整手写公式并转为标准 LaTeX。

#### 3.4.2 引导式答疑
- 当用户提问时，系统默认先给出解题思路提示或相关知识点的 Wiki 链接，引导用户独立思考。
- 用户可主动点击"查看完整解析"来获取详细的步骤讲解。
- 系统须避免直接给出完整答案（除非用户明确要求）。

#### 3.4.3 上下文感知
- AI 辅导应能调取用户历史错题、学习进度、常错知识点，在答疑时结合个人情况给出针对性提醒（例如："你在类似题目中曾犯过计算错误，注意检查符号"）。

#### 3.4.4 追问与多轮对话
- 支持用户就解答内容进行自然语言追问，系统应能提供多轮对话式深入讲解。

#### 3.4.5 答案溯源
- AI 回答应标注所引用的 Wiki 页面来源，格式为 `> [来源：XXX知识点页面]`。
- 用户可点击来源跳转到 Wiki 对应页面查看原文。

#### 3.4.6 知识缺口后台记录（用户无感知）
- AI 辅导检测到用户问题无法命中 Wiki 知识库时，系统应在后台自动记录该问题涉及的疑似新知识点或提问文本。
- 记录应汇总至管理后台的知识缺口列表，由内容团队后续统一处理。
- 终端用户不感知该机制，无任何主动上报入口。

### 3.5 错题管理（P0）

#### 3.5.1 错题自动记录
- 诊断测试、日常练习、阶段检测中的所有错题应自动收录进入个人错题本。
- 记录内容包含：题目、用户答案、正确答案、解析、错误类型标签、关联知识点。

#### 3.5.2 错题分类与归因
- 系统应自动将错题归类到对应知识点，并标记错误类型（概念不清/计算失误/审题偏差/方法错误）。

#### 3.5.3 艾宾浩斯复习
- 基于艾宾浩斯遗忘曲线，系统应为每道错题自动排布复习计划，在遗忘临界点提醒用户重练。
- 复习间隔遵循（1, 2, 4, 7, 15 天）。
- 重练正确后调整复习间隔；连续 3 次正确可移出复习队列。

#### 3.5.4 同类题推荐
- 针对每道错题，系统应自动推荐至少 2 道同类变式题（考察同一知识点，题干不同），供用户巩固训练。
- 同类题也纳入错题跟踪体系。

### 3.6 智能信息中枢（P0）

#### 3.6.1 政策信息采集
- 系统应定期（至少每周）从研招网（yz.chsi.com.cn）爬取考研政策、国家线、报名时间、考试流程等公开信息。
- 信息应自动编译为结构化 Wiki 页面，标注信息发布日期与来源。

#### 3.6.2 院校招生信息采集
- 用户添加目标院校后，系统应定期抓取该校研究生院官网的招生简章、专业目录、复试分数线、录取数据等。
- 信息应结构化存储，并支持按院校、专业筛选。

#### 3.6.3 个性化推送
- 基于用户画像中的目标院校、专业、备考年份，系统应在关键节点（如大纲发布、简章更新、国家线公布、调剂系统开放）主动推送相关信息摘要。
- 推送方式包含站内通知和邮件。

#### 3.6.4 差异对照
- 系统应能自动对比同一院校相邻两年的招生简章、专业目录、分数线等，标记增/删/改项，生成对照表。
- 若科目变更影响用户，系统主动推送预警。

### 3.7 阶段检测与模考（P1）

#### 3.7.1 自动组卷
- 根据用户当前学习阶段（基础/强化/冲刺），系统应能从题库中自动组卷，覆盖已完成学习的知识点。
- 用户可自定义科目、章节范围、题型比例、难度等级。

#### 3.7.2 限时模考
- 系统应提供全真模拟考试环境，包含倒计时、答题卡模拟。
- 模考结束后自动批改并生成详细诊断报告。

#### 3.7.3 阶段报告
- 每完成一个阶段检测，系统应更新用户的知识状态，并与上次检测结果对比，展示进步与未改善的薄弱点。

### 3.8 智能择校辅助（P1）

#### 3.8.1 多维画像构建
- 系统应整合用户本科院校、专业、GPA、英语水平、目标城市偏好等信息，结合最近 3 次诊断/模考成绩预估分数区间，构建择校画像。

#### 3.8.2 院校推荐
- 基于用户画像与院校招生数据，系统应推荐"保底-稳妥-冲刺"三个梯度的院校列表，至少 6 所（每档 2 所）。
- 每个院校应展示竞争指数、核心考核要点、报录比趋势等关键信息。

#### 3.8.3 信息验证提醒
- 每项推荐结果底部显示"建议前往院校官网核实录取数据和考试科目"，并提供官网直达链接。

### 3.9 能力可视化（P1）

#### 3.9.1 个人数据看板
- 展示学习时长分布、各科目投入比例、任务完成率趋势、正确率变化等关键指标。

#### 3.9.2 知识状态雷达图
- 以雷达图形式展示各知识模块的掌握程度，不同掌握度用颜色区分。
- 点击雷达图区块可跳转到对应 Wiki 知识点列表。

#### 3.9.3 成长曲线
- 按时间展示历次诊断/模考得分变化曲线，标记关键节点（如计划调整、强化训练等）。

#### 3.9.4 进度对标（匿名）
- 在用户授权前提下，提供与同目标院校/同专业考生的匿名进度对比，帮助用户客观评估备考位置。

### 3.10 用户系统与基础功能（P0）

#### 3.10.1 注册与登录
- 支持手机号验证码注册登录、微信扫码登录。
- 首次登录后引导完成基本信息填写和目标设置。

#### 3.10.2 个人信息管理
- 用户可管理自己的基本信息、报考意向（目标院校、专业、科目类别）、学习偏好。

#### 3.10.3 数据导出
- 用户应能导出自己的错题本为 PDF（包含题目、答案、解析、错误标签）。
- 学习报告支持导出为 PDF 或 Excel。

## 四、非功能需求

### 4.1 性能

| 指标 | 要求 |
|------|------|
| AI 辅导首字响应时间 | < 2 秒（P95） |
| 诊断组卷生成时间 | < 10 秒 |
| 计划生成时间 | < 15 秒 |
| 页面加载时间（首屏） | < 3 秒 |
| 并发用户支持 | 初期支持 500 并发 |

### 4.2 可靠性

| 指标 | 要求 |
|------|------|
| 系统可用性 | ≥ 99.5%（月度） |
| AI 服务 Failover | 至少配置两个 LLM Provider，自动切换 |
| 数据备份 | 每日自动备份，可恢复到任意最近 7 天内的时间点 |

### 4.3 安全性

- 用户密码哈希存储，传输采用 TLS 加密。
- 学习数据与个人身份数据物理隔离存储。
- 所有 API 接口均需鉴权，敏感操作需二次验证。
- 第三方 LLM 调用不得上传可识别个人身份的数据。
- 招生信息采集遵守目标站点 robots.txt，不进行破坏性爬取。
- **知识库写入接口不对外开放**，仅管理后台可调用。

### 4.4 可维护性

- 前端组件化开发，后端遵循 RESTful API 设计规范。
- 代码仓库保持清晰的模块划分，Wiki 知识库与业务代码分仓管理。
- AGENTS.md 和 CONSTITUTION.md 维护在项目根目录，作为项目治理的核心文档。

### 4.5 可扩展性

- 知识库架构支持新科目（英语、政治、计算机等）无缝扩展，新增科目只需增加对应 raw/ 目录和 Wiki 编译规则。
- 题库支持按科目、知识点、题型、难度等多维度扩展。
- 信息中枢支持添加新的院校信息来源，采集模块插件化。
- **知识库的读写权限体系明确分离**：用户侧仅开放读取接口，管理后台提供完整写入流水线。

| 智能择校 | — | 画像构建、院校推荐、信息验证提醒 |
