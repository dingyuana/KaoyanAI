## 一、引言

### 1.1 目的

本文档定义 **Kaoyan Wiki 考研智能学习助手** 的总体技术架构，明确 **模块A（传统Web应用）** 与 **模块B（Hermes + LLM Wiki 知识底座）** 的职责边界、技术选型及协作方式。

### 1.3 两大模块职责边界

| 维度 | 模块A: 传统Web应用 | 模块B: Hermes + LLM Wiki 知识底座 |
|------|-------------------|----------------------------------|
| **核心职责** | 用户交互、业务逻辑、数据持久化 | 知识编译、智能检索、AI生成、知识进化 |
| **技术栈** | Next.js + FastAPI + PostgreSQL + Redis | Hermes框架 + Milvus + Neo4j + Git + LLM |
| **数据主权** | 用户数据、错题记录、学习计划、院校信息 | Wiki知识页面、知识图谱、向量索引、编译规则 |
| **访问权限** | 终端用户直接访问 | 仅模块A后端可调用，终端用户不直接访问 |
| **部署方式** | 云服务器 + 容器化 | 独立服务器或同机部署，通过内网API通信 |

## 三、模块B: Hermes + LLM Wiki 知识底座

### 3.1 Hermes 智能体框架

| 组件 | 功能 | 本项目应用 |
|------|------|-----------|
| **技能系统** | 定义可复用的程序性知识，标准化为 `SKILL.md` | `llm-wiki`（知识编译）、`tutor`（AI辅导）、`diagnosis`（诊断出题）、`planner`（规划生成）、`info-hub`（信息采集）、`exam`（模考）、`school-selector`（择校） |
| **记忆系统** | 四层记忆架构（对话记录→执行提炼→语义理解→技能调用） | 用户学习画像存储、AI辅导对话历史、知识缺口统计 |
| **Nudge Engine** | 定时任务调度与提醒 | 信息采集、知识缺口检测、错题复习提醒、计划动态调整 |
| **LLM网关** | 多Provider路由与Failover | 统一管理DeepSeek、通义千问、GLM等模型调用 |

### 3.2 LLM Wiki 知识编译引擎

#### 三层架构

```
~/.hermes/wiki/
├── raw/                    # 原始资料层（只增不改）
│   ├── math_2/
│   │   ├── wu_lecture/     # 武忠祥课程（主干）
│   │   └── zhangyu_lecture/# 张宇课程（分支）
│   └── syllabus/           # 历年大纲PDF
│       ├── syllabus_2025.pdf
│       └── syllabus_2026.pdf
│
├── wiki/                   # 知识编译层（LLM维护）
│   ├── math_2/
│   │   ├── 函数与极限/
│   │   │   ├── 极限的定义.md
│   │   │   ├── 极限的计算.md
│   │   │   └── ...
│   │   ├── 导数与微分/
│   │   └── ...
│   ├── info/               # 招生信息Wiki（info-hub技能编译）
│   └── index.md            # 全局导航索引
│
└── AGENTS.md               # LLM编译指令手册
```

#### 编译流水线（四阶段）

```
raw/ 新资料
    │
    ▼
阶段1: 资料预处理
    markitdown (PDF→MD) + Whisper (音视频→文本) + LLM提炼 (逐字稿→高密度笔记)
    输出: processed/ (Clean MD)
    │
    ▼
阶段2: LLM 编译
    主干模式: 全量编译为Wiki基线
    分支模式: 差异提取，轻量接入已有页面
    严格遵循 AGENTS.md 规则
    输出: wiki/ (结构化Markdown)
    │
    ▼
阶段3: 知识图谱构建
    实体识别 + 关系抽取 → Neo4j图谱存储
    Milvus向量索引
    输出: knowledge-graph
    │
    ▼
阶段4: 版本管理
    Git自动提交 + 向量索引增量更新 + index.md自动更新
```

### 3.3 AGENTS.md 核心规则（摘要）

- **页面结构**：定义、公式(LaTeX)、名师精讲、例题、易错点、来源标注
- **主干+分支**：分支仅提取差异点，以“补充视角”或“方法对比”接入，不覆盖主干
- **链接规范**：首次出现的关键概念必须创建内链
- **引导式辅导**：默认先给提示思路，不直接输出完整答案
- **知识复利**：仅后台管理员可触发编译，终端用户无写入权限
- **更新策略**：大纲发布后自动对比差异，精准更新受影响页面


### 4.2 典型业务流程

#### 流程1: AI辅导（用户提问）

```
用户 (模块A前端)
    │
    │ POST /api/tutor/chat {question, image?}
    ▼
模块A后端 (FastAPI)
    │
    │ 1. 鉴权 (JWT)
    │ 2. 图片预处理 (如有多模态输入, 调用OCR/Whisper)
    │ 3. 内网API调用: POST /api/hermes/tutor/chat
    │    Headers: X-API-Key, X-User-ID
    │    Body: {question_text, user_context: {error_book_summary, study_phase}}
    ▼
模块B: Hermes tutor技能
    │
    │ 1. 检索Wiki相关切片 (调用知识库检索接口)
    │ 2. 调取用户记忆 (近30天错题、常错知识点)
    │ 3. 生成引导式回答 (遵循AGENTS.md规范)
    │    ├── 命中Wiki: 展示思路提示, 隐藏完整解析
    │    └── 未命中Wiki: 生成通用引导 + 后台记录知识缺口
    │ 4. 更新记忆系统
    │
    ▼
返回: {hint_text, full_solution (可选), source_pages: [{slug, title}], gap_recorded: bool}
    │
    ▼
模块A后端 → 前端渲染
    │
    │ 前端展示:
    │ · 引导提示 (默认展示)
    │ · "查看完整解析" 按钮 (用户主动点击后才展示)
    │ · 来源引用链接 (可点击跳转Wiki页面)
    │ · 个性化错题提醒
```

#### 流程2: 学习诊断

```
用户 (模块A前端)
    │
    │ POST /api/diagnosis/start {subject: "math_2"}
    ▼
模块A后端
    │
    │ 1. 鉴权
    │ 2. 调用模块B: POST /api/hermes/diagnosis/generate
    │    Body: {user_id, subject, previous_diagnosis_summary}
    ▼
模块B: Hermes diagnosis技能
    │
    │ 自适应组卷 (基于IRT或分层抽样)
    │ 返回: {questions: [{id, type, content, options, difficulty}]}
    │
    ▼
前端展示题目 → 用户作答 → 提交答案
    │
    │ POST /api/diagnosis/submit {answers: [{question_id, user_answer}]}
    ▼
模块A后端
    │
    │ 调用模块B: POST /api/hermes/diagnosis/grade
    │    Body: {user_id, questions, user_answers}
    ▼
模块B: Hermes diagnosis技能
    │
    │ 1. 客观题自动批改
    │ 2. 主观题LLM步骤级批改
    │ 3. 薄弱点归因 (概念/计算/审题/方法)
    │ 4. 生成诊断报告
    │ 5. 更新记忆系统 (用户知识画像)
    │
    ▼
返回: {score, correct_count, weak_points: [{knowledge_point_id, error_type, count}], report_text}
    │
    ▼
模块A后端 → 存储诊断记录到PostgreSQL → 前端渲染报告页面
    │
    │ 后续触发: planner技能根据诊断结果生成/调整学习计划
```

#### 流程3: 知识编译（管理员触发）

```
内容管理员 (模块A前端管理后台)
    │
    │ POST /api/admin/compile/trigger
    │ Body: {mode: "backbone", source_dir: "wu_lecture", subject: "math_2"}
    ▼
模块A后端
    │
    │ 1. 鉴权 (角色必须为 content_admin)
    │ 2. 调用模块B: POST /api/hermes/admin/compile
    │    Headers: X-API-Key (管理端密钥)
    │    Body: {mode, source_dir, subject}
    ▼
模块B: Hermes llm-wiki技能
    │
    │ 阶段1: 资料预处理 (markitdown + Whisper + LLM提炼)
    │ 阶段2: LLM编译 (主干/分支模式, 遵循AGENTS.md)
    │ 阶段3: 知识图谱构建 (Neo4j + Milvus)
    │ 阶段4: 版本管理 (Git提交 + 索引更新)
    │
    ▼
返回: {status: "completed", pages_created: 45, pages_updated: 12, commit_hash: "abc123"}
    │
    ▼
模块A后端 → 前端展示编译结果通知
```

### 4.3 数据同步策略

| 数据类型 | 主存储 | 同步方向 | 同步方式 |
|----------|--------|----------|----------|
| 用户基本信息 | PostgreSQL (模块A) | A → B | API调用时携带 `X-User-ID`，Hermes记忆系统按用户ID存储画像摘要 |
| 学习记录/错题 | PostgreSQL (模块A) | A → B | 诊断/练习完成后，模块A将摘要写入Hermes记忆系统（语义理解层） |
| Wiki知识页面 | Git + Milvus + Neo4j (模块B) | B → A | 模块A通过 `/api/hermes/knowledge/search` 实时查询，不做本地缓存 |
| 知识缺口列表 | Hermes记忆系统 (模块B) | B → A | 模块A管理后台通过 `/api/hermes/admin/gap-list` 拉取展示 |
| 用户画像摘要 | Hermes记忆系统 (模块B) | B → A | 模块A需要时通过 `/api/hermes/memory/{user_id}/profile` 查询 |

## 六、关键技术决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 模块A与B的通信方式 | RESTful API (内网) | 解耦清晰，模块A可独立迭代，模块B可作为独立服务扩展 |
| 用户数据归属 | 模块A (PostgreSQL) | 用户隐私数据与知识底座物理隔离，符合数据安全合规要求 |
| 知识库归属 | 模块B (Git + Milvus + Neo4j) | LLM Wiki编译、检索、图谱均在同一体系内，避免跨模块同步 |
| AI辅导前端渲染 | 流式响应 (SSE) | 引导式辅导需要逐段展示思考过程，SSE比轮询更自然 |
| LLM调用入口 | 统一走模块B的Hermes LLM网关 | 多Provider路由与Failover集中管理，模块A不直接调用LLM |
| 知识编译触发 | 仅管理后台手动触发 + 定时任务 | 防止自动编译质量失控，人工审核保证Wiki基线稳定 |


## 七、安全设计

| 安全措施 | 实现位置 | 说明 |
|----------|----------|------|
| 用户认证 | 模块A JWT | 终端用户登录鉴权 |
| API调用鉴权 | 模块A → 模块B | API Key + IP白名单（内网） |
| 管理操作鉴权 | 模块A 后端 | 角色检查（content_admin / system_admin） |
| PII保护 | 模块A → 模块B | 传输时仅传 `user_id`，不传真实姓名/手机号 |
| 知识库写入 | 模块B | 仅 `/api/hermes/admin/*` 路由可写，普通查询接口只读 |
| 数据传输 | 全链路 | TLS加密（公网）+ 内网明文（模块A→B） |


## 八、技术风险与应对

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 模块B服务不可用 | 高 | 模块A增加熔断机制（如 circuit breaker），AI辅导降级为通用LLM回答 |
| LLM生成质量不稳定 | 高 | AGENTS.md约束 + 引导式Prompt；输出经规则校验 |
| 两大模块API契约变更 | 中 | 版本化API（/v1/、/v2/）；契约测试 |
| Hermes框架版本升级 | 中 | 锁定主版本号；测试环境充分验证后再升级 |
| 知识编译耗时过长 | 中 | 异步任务 + 并行切片处理；增量编译模式 |
| 向量检索延迟高 | 中 | Milvus索引优化；Redis缓存热点Wiki切片 |
| 多模型API调用成本 | 中 | 国产模型优先；高频问题答案缓存 |
