## 二、MVP 阶段（3-4周）

### 目标

验证"基于知识库的考研问答"这一核心假设是否成立。

### 核心假设

- 学生愿意用一个 AI 问答工具来辅助复习
- AI 的回答比翻书查资料更快更准
- 数学公式能正确渲染

### MVP 功能范围

只做一件事：**在一个学科内，用自然语言提问，获得基于知识库的回答**。

具体：
- 学科：只做数学（积累内容后扩展英语、政治）
- 问答：输入问题 → 流式返回答案 → 显示引用来源
- 知识库：手动管理 20-30 个核心概念 MD 文件
- 前端：单页 HTML，纯前端，无需构建
- 后端：单 FastAPI 服务，glob 读 MD 文件，无数据库
- LLM：Claude 或 OpenAI，单模型调用

### 里程碑

| 阶段 | 目标 | 交付物 |
|------|------|--------|
| M0 | 项目初始化完成 | 代码骨架 + 规范文档 + 5个数学概念MD |
| M1 | MVP上线 | 可用的问答系统，真实用户体验反馈 |

### M0：项目初始化（第1周）

- [ ] 整理 GitHub 仓库
- [ ] 初始化 FastAPI 后端（单文件）
- [ ] 创建单页前端 HTML
- [ ] 准备 5 个数学核心概念 MD 文件（覆盖极限/导数/积分）
- [ ] 完成本计划文档（本文件）
- [ ] 完成 `SPEC.md`（MVP规格说明）

### M1：MVP开发与上线（第2-3周）

- [ ] 后端：知识检索（glob + keyword search）
- [ ] 后端：LLM 问答（调用 API，流式返回）
- [ ] 前端：提问 + 流式显示回答 + 引用来源展示
- [ ] 前端：数学公式渲染（KaTeX）
- [ ] 后端：学科切换（数据结构预留，暂时只开数学）
- [ ] 知识库：扩充到 20-30 个数学概念
- [ ] 部署到 Railway / Render（单命令部署）
- [ ] 邀请 10-20 名真实用户试用

### MVP 验收标准

- [ ] 用户输入数学问题，3秒内返回回答
- [ ] 回答中的数学公式正确渲染
- [ ] 每条回答附带来源文件名
- [ ] 不在知识库内的内容，AI 主动说明"无法回答"
- [ ] 可在手机浏览器正常使用
- [ ] 10 个用户同时访问不崩溃

## 四、决策机制

### MVP 阶段判断标准

**通过条件**（满足任意2条）：
- 用户留存率 > 30%（次日还来用）
- 用户主动推荐给他人
- 平均每次会话 > 3 个问题

**不通过条件**（满足任意1条）：
- 上线2周后日活 < 5人
- 用户反馈"不如直接翻书"

### 通过后

继续 M2-M5 的 Commercial 开发计划。

### 未通过

重新审视核心假设：
- 是产品方向问题（不需要这个功能）→ 调整方向
- 是产品体验问题（需求存在但没做好）→ 优化体验
- 是推广问题（产品OK但用户不知道）→ 加大推广
