# 考研知识库问答系统 · 中期开发目标

> 版本：1.0 | 更新日期：2026-05-14
>
> 本文档定义项目从 MVP 验证阶段迈向可部署产品的中期开发目标。
> 目标是：**将当前可运行的 MVP 原型打磨成一个可部署、可体验、可迭代的正式产品**。

## 二、中期开发目标

### 目标 1：产品可部署（P0）

**定义**：用户可以通过互联网访问并使用问答系统。

**关键结果**：
- [ ] Docker Compose 一键启动全部服务
- [ ] Nginx 反向代理配置完成
- [ ] 前后端容器化，镜像构建自动化
- [ ] CI/CD 流水线（GitHub Actions）搭建
- [ ] 可在云服务器（1C2G）上稳定运行

**验收标准**：
- `docker-compose up -d` → 系统可用
- 前端 `/kaoyan` 正常访问
- 后端 API 可正常调用
- 重启后数据不丢失

---

### 目标 2：LLM 真实集成（P0）

**定义**：后端接入真实 LLM API，提供高质量的、基于知识库的智能回答。

**关键结果**：
- [ ] OpenAI / Claude API 真实调用
- [ ] 流式输出从 LLM 实时推送（当前为模拟）
- [ ] 知识库上下文构建优化（控制 token 消耗）
- [ ] 无知识库内容时优雅降级（"无法回答"）
- [ ] API Key 通过环境变量配置

**验收标准**：
- 真实问题获得基于知识库的准确回答
- 流式输出首字延迟 < 500ms
- 超出知识库范围的问题明确提示
- 回答附带来源引用

---

### 目标 3：质量保障体系（P0）

**定义**：建立测试、类型检查、代码规范三位一体的质量保障体系。

**关键结果**：
- [ ] 后端单元测试覆盖核心模块（检索 + LLM 调用）
- [ ] 前端组件测试（ChatInterface 核心交互）
- [ ] TypeScript 严格模式无报错
- [ ] Python 类型注解完整
- [ ] ESLint + Prettier 配置

**验收标准**：
- `pytest` 测试通过率 100%
- `npm run lint` 无错误
- TypeScript 编译无报错
- 测试覆盖率 > 60%（核心模块）

---

### 目标 4：概念浏览功能（P1）

**定义**：用户可以通过树形结构浏览知识库概念，点击查看详情。

**关键结果**：
- [ ] `ConceptTree` 组件：按章节/知识领域组织概念列表
- [ ] `ConceptDetail` 组件：Markdown 渲染概念详情
- [ ] 后端 `/concepts/{subject}` 接口支持层级结构返回
- [ ] 搜索/筛选功能（按章节/关键词）
- [ ] 概念详情中显示关联习题

**验收标准**：
- 用户可浏览数学全部 421 个概念
- 点击概念显示完整内容（含 LaTeX）
- 概念详情页显示关联习题入口

---

### 目标 5：知识库价值最大化（P1）

**定义**：充分利用已有 942 个 Wiki 文件，建立概念-方法-习题的关联体系。

**关键结果**：
- [ ] 习题关联概念：查看习题时展示涉及的概念
- [ ] 概念关联习题：查看概念时展示相关习题
- [ ] INDEX.yaml 中的 `related` 字段在前端展示
- [ ] 习题支持按类型（选择/填空/解答）筛选

**验收标准**：
- 概念页显示 3-5 道关联习题
- 习题页显示 3-5 个涉及的概念
- 关联准确率 > 80%

---

### 目标 6：开发者体验完善（P1）

**定义**：新开发者可在 5 分钟内完成本地开发环境搭建。

**关键结果**：
- [ ] `.env.example` 文件（所有配置项说明）
- [ ] `Makefile` 或 `justfile`（常用命令快捷入口）
- [ ] 贡献指南 (`CONTRIBUTING.md`)
- [ ] 开发环境 Docker Compose（数据库/依赖服务）
- [ ] Wiki 知识库变更记录/操作指南

**验收标准**：
- 新机器 `make setup && make dev` → 系统运行
- 环境变量缺失时给出清晰提示

---

### 目标 7：性能与稳定性（P2）

**定义**：系统在典型负载下保持稳定，响应时间满足用户期望。

**关键结果**：
- [ ] LLM 响应缓存（重复问题秒回）
- [ ] 知识库检索优化（索引预加载）
- [ ] 后端错误监控（Sentry / 日志）
- [ ] 前端加载状态骨架屏
- [ ] API 限流保护

**验收标准**：
- 10 并发用户无明显卡顿
- 重复问题回答时间 < 1s
- 后端 5xx 错误率 < 0.1%

---

### 目标 8：多学科扩展基础（P2）

**定义**：为英语/政治学科建立框架，积累初始内容。

**关键结果**：
- [ ] 英语学科知识库目录结构（raw/L3）
- [ ] 政治学科知识库目录结构（raw/L3）
- [ ] 学科切换后正确路由到对应知识库
- [ ] 至少 5 个英语 L3 文件（词汇/语法）
- [ ] 至少 5 个政治 L3 文件（马原/毛概）

**验收标准**：
- 前端切换学科后 API 调用正确
- 学科无内容时给出友好提示
- 新学科知识库可独立维护

## 四、里程碑规划

### M4：功能完善与部署（当前阶段 — 预计 3-4 周）

```
第 1 周：LLM 真实集成 + 错误处理完善
第 2 周：Docker 化部署 + Nginx 配置
第 3 周：测试体系建立 + CI/CD
第 4 周：概念浏览功能 + 文档更新
```

**交付标准**：
- [ ] LLM 真实流式问答可用
- [ ] `docker-compose up` 一键部署
- [ ] pytest + ESLint 通过
- [ ] 概念树浏览可用
- [ ] 所有文档与代码一致

### M5：体验优化与扩展（预计 2-3 周）

```
第 1 周：习题关联 + 知识库价值深挖
第 2 周：性能优化（缓存/索引）
第 3 周：英语/政治学科初始化
```

**交付标准**：
- [ ] 概念 ⇄ 习题双向关联
- [ ] 重复问题缓存命中
- [ ] 英语/政治框架就绪

### M6：测试推广（预计 2 周）

```
第 1 周：邀请 10-20 名真实用户测试
第 2 周：收集反馈，P0/P1 Bug 修复
```

**交付标准**：
- [ ] 10+ 真实用户体验
- [ ] MVP 验证结论（通过/不通过）
- [ ] 根据反馈的迭代计划

## 五、风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| LLM API 费用超预期 | 中 | 高 | 设置 token 上限 + 缓存 + 降级到小模型 |
| Wiki 文件编码问题 | 低 | 中 | 统一 UTF-8 + 写入时验证 |
| 单服务器性能瓶颈 | 中 | 中 | 分离前后端部署，引入 CDN |
| 知识库规模膨胀 | 中 | 低 | 延迟引入 Elasticsearch 即可 |
| 用户留存不足 | 中 | 高 | MVP 验证前置，快速 pivot |
