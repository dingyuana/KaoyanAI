## 二、中期开发目标

### 目标 1：408 知识库 L3 编译（P0）

**定义**：将 4 门 408 专业课的 837 个 RAW 文件编译为结构化 L3 应用文档。

**关键结果**：
- [ ] 数据结构：编译 L3 概念/方法/习题文档
- [ ] 计算机组成原理：编译 L3 概念/方法/习题文档
- [ ] 计算机网络：编译 L3 概念/方法/习题文档
- [ ] 操作系统：编译 L3 概念/方法/习题文档
- [ ] 每门课至少 20 个 L3 概念文档 + 5 个方法文档 + 5 个习题文档
- [ ] L3 文档遵循 Frontmatter + 模板规范

**验收标准**：
- 4 门课 L3 文件可被 `wiki_retriever.py` 正常检索
- `GET /concepts/{subject}` 返回 CS 学科的概念列表
- 问答能命中 CS 知识库内容

---

### 目标 2：多学科后端适配（P0）

**定义**：后端支持 7 个学科（math / english / politics / ds / arch / net / os），前端可切换。

**关键结果**：
- [ ] `config.py` 中 SUBJECTS 扩展为 7 学科
- [ ] `wiki_retriever.py` 自动发现可用学科（已有 get_subjects() 基于目录检测）
- [ ] `main.py` 中 subject 校验从硬编码列表改为动态检测
- [ ] 前端学科切换 UI 更新为 7 学科
- [ ] 学科无 L3 内容时返回友好提示

**验收标准**：
- 前端可看到全部 7 个学科
- 切换数学与任意 CS 学科，API 调用正确路由
- 学科有 L3 内容时正常回答，无 L3 时提示"暂无内容"

---

### 目标 3：质量保障体系（P0）

**定义**：建立测试、类型检查、代码规范三位一体的质量保障体系。

**关键结果**：
- [ ] 后端单元测试覆盖核心模块（检索 + LLM 调用 + 异常处理）
- [ ] 前端组件测试（ChatInterface 核心交互）
- [ ] TypeScript 严格模式无报错
- [ ] Python 类型注解完整
- [ ] ESLint + Prettier 配置

**验收标准**：
- `pytest` 测试通过率 100%
- `npm run lint` 无错误
- TypeScript 编译无报错
- 测试覆盖率 > 60%（核心模块）

---

### 目标 4：概念浏览功能（P1）

**定义**：用户可以通过树形结构浏览知识库概念，点击查看详情。

**关键结果**：
- [ ] `ConceptTree` 组件：按章节/知识领域组织概念列表
- [ ] `ConceptDetail` 组件：Markdown 渲染概念详情
- [ ] 后端 `/concepts/{subject}` 接口已支持层级结构（已有 chapter 分组）
- [ ] 搜索/筛选功能（按章节/关键词）
- [ ] 概念详情中显示关联习题

**验收标准**：
- 用户可浏览数学全部 + CS 各学科概念
- 点击概念显示完整内容（含 LaTeX）
- 概念详情页显示关联习题入口

---

### 目标 5：知识库价值最大化（P1）

**定义**：充分利用已有知识库，建立概念-方法-习题的关联体系。

**关键结果**：
- [ ] 习题关联概念：查看习题时展示涉及的概念
- [ ] 概念关联习题：查看概念时展示相关习题
- [ ] INDEX.yaml 中的关联字段在前端展示
- [ ] 习题支持按类型（选择/填空/解答）筛选

**验收标准**：
- 概念页显示 3-5 道关联习题
- 习题页显示 3-5 个涉及的概念
- 关联准确率 > 80%

---

### 目标 6：开发者体验完善（P1）

**定义**：新开发者可在 5 分钟内完成本地开发环境搭建。

**关键结果**：
- [ ] `.env.example` 文件（所有配置项说明）
- [ ] `Makefile` 或 `justfile`（常用命令快捷入口）
- [ ] 贡献指南 (`CONTRIBUTING.md`)
- [ ] 开发环境快捷启动文档

**验收标准**：
- 新机器执行 `pip install -r requirements.txt && uvicorn main:app --reload --port 8001` 后端可用
- 前端 `npm install && npm run dev` 正常启动
- 环境变量缺失时给出清晰提示

### 目标 7：Docker 部署（发布阶段 — P2）

**定义**：产品发布时，通过 Docker Compose 一键启动全部服务。

> ⚠️ 开发阶段保持本地运行（uvicorn + npm run dev），Docker 仅在发布时使用。

**关键结果**：
- [ ] 现有 `docker-compose.yml` + `Dockerfile` 验证可用
- [ ] Nginx 反向代理配置完成
- [ ] CI/CD 流水线（GitHub Actions）搭建
- [ ] 可在云服务器（1C2G）上稳定运行

**验收标准**：
- `docker-compose up -d` → 系统可用
- 前端正常访问，后端 API 可正常调用
- 重启后数据不丢失

### 目标 8：多学科扩展（P2）
