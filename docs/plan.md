## 二、MVP 阶段（1-2周）

### 目标

验证"考研数学知识库 + AI 问答"这一产品方向是否成立。

### 技术栈（最简化）

| 层 | 工具 | 说明 |
|---|------|------|
| 前端 | Next.js（简化版） | 单页问答界面，无复杂路由 |
| 后端 | FastAPI（单文件） | 单 `main.py`，不过度设计 |
| 检索 | glob + 关键词匹配 | 直接读 MD 文件，不引入数据库 |
| LLM | Claude/GPT API | 按调用量付费，不自建GPU服务 |
| 知识库 | Wiki MD 文件 | L1→L2→L3 结构，Hermes 管理 |
| 部署 | Vercel + Railway | 免费额度够用，Git推送即部署 |

### 里程碑

| 阶段 | 任务 | 交付物 |
|------|------|--------|
| M0 | 项目初始化 | 代码骨架 + Wiki框架 + 5个L3文件 |
| M1 | 后端开发 | FastAPI 服务，检索 + LLM 调用，跑通 |
| M2 | 前端开发 | Next.js 问答界面，API 对接 |
| M3 | 部署上线 | Vercel + Railway，真实用户体验 |
| M4 | 反馈迭代 | 根据用户反馈优化（1-2轮） |

### M0：项目初始化（第1天）

- [ ] 初始化 Next.js 项目（`frontend/`）
- [ ] 初始化 FastAPI 项目（`backend/main.py`）
- [ ] 完善 Wiki 框架目录（raw/L2/L3/TEMPLATES/INDEX.yaml）
- [ ] 创建 5 个数学 L3 文件（极限/导数/积分/微分方程/级数）
- [ ] 配置 GitHub 仓库

### M1：后端开发（第2-3天）

- [ ] 实现 `/api/v1/query` 接口（问答）
- [ ] 实现 `/api/v1/subjects` 接口（学科列表）
- [ ] 实现 `search.py`（glob 读 MD + 关键词匹配）
- [ ] 接入 LLM API（非流式先上）
- [ ] 对接 5 个 L3 文件，检索测试通过
- [ ] 后端部署到 Railway

### M2：前端开发（第4-6天）

- [ ] 创建 `app/page.tsx`（问答首页）
- [ ] 实现 `ChatPanel.tsx`（提问 + 回答展示）
- [ ] 实现 `SubjectSwitcher.tsx`（学科切换 UI）
- [ ] 实现 LaTeX 渲染（KaTeX）
- [ ] 实现引用来源展示
- [ ] 对接后端 API
- [ ] 前端部署到 Vercel

### M3：联调上线（第7天）

- [ ] 前后端联调
- [ ] 知乎/小红书/微信群发布，邀请10-20名真实用户试用
- [ ] 收集反馈，记录问题

### M4：反馈迭代（第8-14天）

- [ ] 根据反馈修复 Bug
- [ ] 扩充知识库（20-30个L3文件）
- [ ] 优化回答质量（调整 prompt）
- [ ] 评估：是否达到验收标准

### MVP 验收标准

**通过条件**（满足任意2条）：
- 用户留存率 > 30%（次日还来用）
- 平均每次会话 > 3 个问题
- 用户主动推荐给他人

**不通过条件**（满足任意1条）：
- 上线2周后日活 < 5人
- 用户反馈"不如直接翻书"

## 四、知识库建设（贯穿全流程）

### 当前状态

- Wiki 框架已建立（`wiki/math/`）
- 模板文件已创建（`TEMPLATES/`）
- L3 文件需你提供原始材料后逐步生成

### 知识库数量目标

| 阶段 | L3 文件数量 | 覆盖范围 |
|------|-----------|---------|
| MVP上线 | 5个 | 极限/导数/积分/微分方程/级数 |
| MVP稳定 | 20-30个 | 覆盖高数上册核心章节 |
| Commercial | 100+ | 覆盖考研数学全部章节 |

### 知识库格式要求

详见 `docs/WIKI.md`（Wiki框架规范）。核心要求：
- 每文件一个概念/方法/习题
- 包含 Frontmatter（title/tags/related）
- 正文用 Markdown + LaTeX
- 长度：500-2000字
