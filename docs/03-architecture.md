## 2. 请求处理流程

### 2.1 问答流程（流式）

```
用户输入问题
       │
       ▼
ChatInterface.handleSubmit()
       │ POST /kaoyan/api/chat/stream
       ▼
Next.js API Route (route.ts)
       │ 转发到 localhost:8001/chat/stream
       ▼
FastAPI chat_stream()
       │
       ├── wiki_retriever.retrieve_knowledge()
       │      ├── 遍历 L3 文件匹配关键词
       │      ├── 收集匹配内容 + 来源
       │      └── 返回 content + sources
       │
       ├── yield SSE: sources
       │
       ├── llm.generate_response(context, question)
       │      ├── Mock 模式：返回首段匹配内容（模拟）
       │      └── 真实模式：调用 LLM API
       │
       ├── yield SSE: chunk (逐行/逐块)
       │
       └── yield SSE: done
              │
              ▼
       ChatInterface 接收 SSE 事件
              │
              ├── onSources → 显示引用来源
              ├── onChunk → 逐步渲染回答（含 KaTeX）
              └── onDone → 完成状态
```

### 2.2 知识检索流程

```
用户问题
    │
    ▼
retrieve_knowledge(question, subject)
    │
    ├── 1. 获取学科 L3 目录路径
    │
    ├── 2. 遍历 concepts/ methods/ exercises/ 子目录
    │      │
    │      └── 对每个 MD 文件：
    │             ├── 读取文件内容
    │             ├── 提取 Frontmatter（标题/标签/锚点）
    │             ├── 正文关键词匹配（re 模块）
    │             └── 匹配成功 → 添加到结果列表
    │
    ├── 3. 结果排序（按匹配度）
    │
    └── 4. 返回 top_k 结果 + 拼接 context
```

## 4. 架构约束

### 4.1 数据流方向

```
用户 → 前端组件 → Next.js API Route → FastAPI → Wiki 文件系统
                                                        ↓
用户 ← 前端组件 ← SSE 流式响应   ← FastAPI ← LLM API / Mock
```

### 4.2 关键约束

- **前端不直接访问 Wiki 文件系统** — 所有数据通过后端 API 获取
- **后端不持有状态** — 无状态服务，无数据库依赖
- **知识库只读** — 代码不修改 Wiki 文件（由 Hermes 工具管理）
- **SSE 为流式唯一协议** — 不使用 WebSocket

### 4.3 端口分配

| 服务 | 端口 | 说明 |
|------|------|------|
| Next.js 前端 | 3000 | 开发服务器 |
| FastAPI 后端 | 8001 | uvicorn 服务 |
| 生产 Nginx | 80/443 | 反向代理（待配置） |

## 5. 与原始设计的偏差

| 原始设计（文档） | 当前实现 | 说明 |
|-----------------|---------|------|
| 单文件 FastAPI | 模块化（4 文件） | 更好的关注点分离 |
| 单页 HTML | Next.js 16 全栈 | 更完善的开发体验 |
| 20-30 个 L3 文件 | 468 个 L3 文件 | 知识库远超预期 |
| Vanilla JS | React + TypeScript | 类型安全 |
| Railway 部署 | 待配置 | 尚未部署 |
| 非流式优先 | 流式优先 | 更好的用户体验 |
