## 一、知识库总体架构

### 1.1 设计理念

考研知识库采用 **Wiki 三层架构**，核心理念是：**原始材料与生成内容分离，索引作为中间层，确保可追溯、可扩展、可维护**。

```
原始材料（教材/讲义/真题）
        │
        ▼  ─── L1 层：原始只读，永久不变
  分块加工
        │
        ▼  ─── L2 层：索引目录，描述特征
  索引生成
        │
        ▼  ─── L3 层：应用文档，面向问答
  文档生成
```

**为什么是三层？**

| 层 | 解决的问题 | 类比 |
|----|-----------|------|
| L1 | 原始材料不可篡改，保证引用可追溯 | 图书馆的原始藏书 |
| L2 | 快速定位知识块，描述概念间关系 | 图书目录卡片 |
| L3 | 面向 LLM 问答的结构化内容 | 经过整理的摘要卡片 |

## 二、三层结构详解

### 2.1 L1 层：原始材料（Raw）

**定位**：永久只读的原始素材层，知识库的"源代码"。

**存储位置**：`{subject}/raw/`

**内容类型**：

| 类型 | 来源 | 示例 |
|------|------|------|
| 教材原文 | 考研数学教材（同济版、张宇等） | `高等数学/极限.md` |
| 讲座转写 | 老师讲课记录 | `高等数学/高等数学-第100讲.md` |
| 方法总结 | 解题方法论 | `概率论与数理统计/【方法】反向思路.md` |
| 习题集合 | 历年真题、习题集 | `exams/基础篇_一元函数微分学的应用.md` |

**核心规则**：
- ✅ **只读**：写入后不可修改，不可删除
- ✅ **保留原貌**：不纠错、不总结、不提炼
- ✅ **完整保存**：LaTeX 公式、图片引用等必须完整
- ❌ **禁止编辑**：即使发现原文笔误，也保留原样

### 2.2 L2 层：索引（Index）

**定位**：知识库的"目录卡片"，描述每个知识块的特征和关系。

**存储位置**：`{subject}/INDEX.yaml`

**索引条目结构**：

```yaml
- anchor: INDEX-math-concept-极限            # L2 锚点 ID（唯一）
  type: concept                               # 类型：concept / method / exercise
  title: 极限                                 # 中文标题
  chapter: 高等数学                           # 所属章节
  raw_concepts:                               # 从 L1 提取的原始概念标签
    - 极限
  perspective: 基础概念                        # 视角
  source: L3生成                               # 来源
  related:                                     # 关联条目
    - INDEX-math-concept-数列极限
    - INDEX-math-concept-导数与微分
  uncertainty: false                           # 是否存在矛盾/不确定性
  processed_to_L3: L3-math-concept-极限        # 已生成的 L3 文档 ID（空=未处理）
```

**核心规则**：
- ✅ **可追加**：新增学科、新概念时添加新条目
- ❌ **不可删除**：已有条目不可删除（可标记废弃）
- ✅ **关联关系**：通过 `related` 字段建立概念间链接

### 2.3 L3 层：应用文档（Generated）

**定位**：面向问答的结构化知识文档，一个概念一个文件。

**存储位置**：`{subject}/L3/{type}/`

**三种文档类型**：

| 类型 | 目录 | 核心内容 | 数量 |
|------|------|---------|:----:|
| **concept** | `L3/concepts/` | 定义 + 直观解释 + 核心要点 + 常见考法 + 注意事项 | 422 |
| **method** | `L3/methods/` | 适用场景 + 方法步骤 + 示例 + 失效情况 | 17 |
| **exercise** | `L3/exercises/` | 题目列表 + 解析 + 考点分布 | 30 |

**L3 文档结构（以 concept 为例）**：

```markdown
---
id: L3-math-concept-极限                # L3 唯一 ID
title: 极限                              # 中文标题
subject: math                            # 所属学科
type: concept                            # 文档类型
level: 3                                 # 层级（固定为 3）
tags: [高等数学, 基础概念]               # 标签
related:                                 # 关联文档
  - concepts/数列极限.md
  - concepts/导数与微分.md
source_anchors:                          # 来源锚点（引用 L1）
  - RAW-math-同济高数上-P023-C07
created: 2026-05-15                      # 创建日期
---

# 极限

## 什么是极限
（正文内容...）

## 典型例题
（例题+解析...）

## 常见错误
（易错点...）
```

## 三、锚点 ID 体系

### 3.1 设计意图

锚点 ID 是知识库的**永久身份标识**，类似 DOI（数字对象标识符）。一旦分配，永不改变、永不重用。

### 3.2 格式定义

| 层级 | 格式 | 示例 |
|------|------|------|
| L1 | `RAW-{学科}-{来源}-P{页码}-C{序号}` | `RAW-math-同济高数上-P023-C07` |
| L2 | `INDEX-{学科}-{类型}-{概念标识}` | `INDEX-math-concept-极限` |
| L3 | `L3-{学科}-{类型}-{文件名}` | `L3-math-concept-极限的概念与性质` |

### 3.3 各字段说明

- **{学科}**：小写英文（math / english / politics）
- **{来源}**：教材简称（同济高数上、概率论...）
- **{页码}**：三位数字页码（P001, P023...）
- **{序号}**：该页上的 Chunk 编号（C01, C02...）
- **{类型}**：concept / method / exercise
- **{文件名}**：文件主名（不含扩展名）

### 3.4 永久性规则（不可违反）

| 规则 | 说明 |
|------|------|
| **永不改变** | ID 分配后不可修改 |
| **永不重用** | ID 废弃后不可用于其他内容 |
| **永不删除** | 废弃条目标记 `deprecated: true`，保留 ID |
| **学科隔离** | 不同学科使用不同前缀，ID 不跨学科 |

## 四、创作全流程

### 4.1 总体流程概览

```
原材料（PDF/讲义/Markdown）
    │
    ▼ 流程1 ─────────────
  材料摄入与分块             →  产出：L1 Raw 文件
    │
    ▼ 流程2 ─────────────
  L2 索引生成               →  产出：INDEX.yaml 条目
    │
    ▼ 流程3 ─────────────
  L3 文档生成               →  产出：L3 应用文档
    │
    ▼ 流程4 ─────────────
  完整性与一致性检查         →  产出：检查报告
```

### 4.2 流程1：材料摄入与分块（L1 生成）

**输入**：PDF 文件 / Markdown 文件 / 真题卷

**输出**：`raw/` 目录下的 L1 Chunk 文件

**操作步骤**：

```
Step 1 - 格式转换
  ├── 文本型 PDF → MarkItDown 转 Markdown
  └── 扫描版 PDF → OCR（Mathpix/MinerU）→ Markdown

Step 2 - 内容分块
  ├── 按页+章节切分
  ├── 每个 Chunk 独立成文件
  └── 确保 LaTeX 公式完整（不被截断）

Step 3 - 分配锚点 ID
  └── 格式：RAW-{来源}-P{页码}-C{序号}

Step 4 - 分类识别
  ├── 概念型 → 纯概念名
  ├── 方法型 → 标注【方法】前缀
  ├── 习题型 → 按基础篇/强化篇分类
  └── 讲座型 → 标注"第N讲"，仅存档不生成 L3

Step 5 - 保存文件
  └── 命名：{学科}_{章节序号}_{标题}.md
```

**分块原则**：

| 内容类型 | 分块规则 |
|----------|---------|
| 定义 | 一个定义 = 一个 Chunk |
| 定理 | 定理完整（含证明）= 一个 Chunk |
| 例题 | 题目 + 解答 = 一个 Chunk |
| 习题 | 单题 = 一个 Chunk |
| 公式推导 | 连续推导步骤不得拆分 |

### 4.3 流程2：L2 索引生成

**输入**：raw/ 目录下的新 Chunk

**输出**：更新后的 INDEX.yaml

**操作步骤**：

```
Step 1 - 读取 Domain SCHEMA
  └── 了解本学科的类型定义和分类体系

Step 2 - 分析 Chunk 内容
  ├── 识别类型：concept / method / exercise
  ├── 提取 raw_concepts（原始概念标签）
  └── 确定 perspective（视角：基础概念/解题方法/易错点）

Step 3 - 生成索引条目
  ├── 分配 L2 锚点 ID：INDEX-{学科}-{类型}-{标识}
  ├── 填写 chapter（所属章节）
  └── 填写 related（已知关联条目）

Step 4 - 写入 INDEX.yaml
  └── 注意：processed_to_L3 暂留空
```

### 4.4 流程3：L3 文档生成

**输入**：INDEX.yaml 中 `processed_to_L3` 为空的条目

**输出**：`L3/{type}/` 目录下的 L3 文档

**操作步骤**：

```
Step 1 - 准备工作
  ├── 读取 Domain SCHEMA.md（了解学科规范）
  ├── 读取 Domain AGENT.md（了解行为约束）
  └── 读取对应 L1 Raw 原文

Step 2 - 确定文档类型
  ├── concept → L3/concepts/
  ├── method  → L3/methods/
  └── exercise → L3/exercises/

Step 3 - 加载模板
  └── 使用 TEMPLATES/ 中对应模板（concept/method/exercise）

Step 4 - 生成文档内容
  ├── 填写 Frontmatter（ID / title / tags / related / source_anchors）
  ├── 引用 L1 原文（带锚点引用）
  ├── 添加 LLM 生成的解释性内容
  ├── 补充示例和常见考法
  └── 建立关联（related 字段）

Step 5 - 验证与保存
  ├── 验证 LaTeX 格式正确
  ├── 验证 source_anchors 指向有效的 L1 锚点
  └── 保存文件：L3-{学科}-{类型}-{标识}.md

Step 6 - 更新 INDEX.yaml
  └── processed_to_L3 填写生成的 L3 文档 ID
```

**L3 文档类型的内容要求**：

| 文档类型 | 必须包含 | 建议包含 |
|----------|---------|---------|
| Concept | 形式化定义、直观解释、核心要点 | 常见考法、注意事项、关联概念 |
| Method | 适用场景、方法步骤（可执行） | 示例、失效情况、替代方法 |
| Exercise | 题目、解析、答案 | 难度标注、考点分布、学习建议 |

### 4.5 完整示例

**场景**：从教材原始材料到生成"极限"概念 L3 文档

**L1 Raw 分块**：
```
raw/高等数学/极限.md
  └── 包含内容：极限定义、极限性质、极限计算例题
  └── 锚点：RAW-math-同济高数上-P023-C07
```

**L2 索引条目**：
```yaml
- anchor: INDEX-math-concept-极限
  type: concept
  title: 极限
  chapter: 高等数学
  related:
    - INDEX-math-concept-数列极限
    - INDEX-math-concept-导数与微分
  processed_to_L3: L3-math-concept-极限
```

**L3 应用文档**：
```
L3/concepts/L3-math-concept-极限.md
  ├── Frontmatter（ID/title/tags/related/source_anchors）
  ├── 什么是极限（基于 L1 原文的直观解释）
  ├── 概率论中的极限（多源对照）
  ├── 典型例题（3 道，含解析）
  ├── 常见题型与解法（表格汇总）
  └── 常见错误（3 个易错点）
```

## 五、文件命名规范总览

### 5.1 Raw 层文件命名

| 文件类型 | 命名格式 | 示例 |
|----------|---------|------|
| 概念型 | `{标题}.md` | `极限.md` |
| 编号型 | `{序号}-{标题}.md` | `01-行列式.md` |
| 方法型 | `【方法】{方法名}.md` | `【方法】反向思路.md` |
| 讲座型 | `{学科}-第{N}讲.md` | `高等数学-第100讲.md` |
| 习题型 | `{基础\|强化}篇_{标题}.md` | `基础篇_一元函数微分学的应用.md` |
| 真题卷 | `exams/{年份}_{科目}_{题号}.md` | `exams/2024_数学一_1.md` |

### 5.2 L3 层文件命名

| 文档类型 | 命名格式 | 示例 |
|----------|---------|------|
| Concept | `L3-{学科}-concept-{标识}.md` | `L3-math-concept-极限.md` |
| Method | `L3-{学科}-method-{标识}.md` | `L3-math-method-洛必达法则.md` |
| Exercise | `L3-{学科}-exercise-P{编号}-{标识}.md` | `L3-math-exercise-P001-一元函数微分学的应用.md` |

### 5.3 命名一致性检查清单

处理新的 raw 文件时，对照以下检查：

- [ ] 文件名是否以 `第N讲` 结尾？→ 讲座转写，仅存档
- [ ] 文件名是否含 `【方法】` 或 `【方法论】`？→ 方法型，检查是否需加 subject 前缀
- [ ] 文件名是否含数字前缀（如 `01-`）？→ 编号型，剥离数字前缀
- [ ] 文件名是否以 `基础篇_` 或 `强化篇_` 开头？→ 习题型，按顺序分配 P 编号
- [ ] 其他情况 → 概念型，直接映射

## 六、质量控制标准

### 6.1 L3 文档验收标准

每份 L3 文档必须满足以下条件方可提交：

**Frontmatter 完整性**：
- [ ] `id` 格式正确且唯一
- [ ] `title` 为中文
- [ ] `subject` 与学科一致
- [ ] `type` 为 concept / method / exercise 之一
- [ ] `tags` 至少包含一个学科标签
- [ ] `source_anchors` 至少有一个有效 L1 锚点
- [ ] `created` 日期格式正确

**内容质量**：
- [ ] 正文结构符合对应模板要求
- [ ] LaTeX 公式渲染正确（无截断、无语法错误）
- [ ] 示例题有完整解答
- [ ] 引用标注了来源锚点
- [ ] 未出现跨学科直接引用
- [ ] 未编造 L1 中不存在的内容

### 6.2 一致性检查

| 检查项 | 频率 | 方法 |
|--------|------|------|
| L2 锚点指向有效 L1 | 每周/每次批量更新后 | 遍历 INDEX.yaml，验证每个 anchor 的对应 L1 文件存在 |
| L3 source_anchors 指向有效 L1 | 每周 | 遍历所有 L3 文档，验证 source_anchors 字段 |
| L2 覆盖率 = processed / total | 每周 | processed_to_L3 非空的条目数 / 总条目数，< 80% 触发警告 |
| 重复内容检测 | 每月 | 检查相同标题/内容的 L1 Chunk 或 L3 文档 |
| concept_map 覆盖度 | 每月 | 检查同义词是否都被映射到标准概念 |

### 6.3 数学学科特有检查

- [ ] LaTeX 行内公式使用 `$...$`，独立公式使用 `$$...$$`
- [ ] 矩阵格式使用 `\begin{pmatrix}...\end{pmatrix}`
- [ ] 分段函数使用 `\begin{cases}...\end{cases}`
- [ ] 数学符号使用标准 LaTeX 语法（如 `\sin` 非 `sin`）
- [ ] 推导步骤完整，无跳跃

## 七、多学科扩展规范

### 7.1 新增学科前置检查清单

决定新增一个学科（如英语、政治）时，需要准备以下内容：

- [ ] **确定学科前缀**（小写英文，如 `english`、`politics`）
- [ ] **创建 SCHEMA.md**（Domain 宪法）—— 基于 `math/SCHEMA.md` 改编
- [ ] **创建 AGENT.md**（Domain AI 约束）—— 基于 `math/AGENT.md` 改编
- [ ] **创建 INDEX.yaml**（初始化空索引文件）
- [ ] **创建目录结构**：
  - `raw/`（L1 原始材料目录）
  - `L3/concepts/`、`L3/methods/`、`L3/exercises/`（可选）
  - `TEMPLATES/`（本学科模板）
  - `_meta/concept_map.yaml`（概念词表）
- [ ] **配置后端**：在 `config.py` 的 `SUBJECTS` 列表中添加学科名
- [ ] **前端确认**：检查前端学科切换 UI 是否需要更新

### 7.2 SCHEMA.md 模版结构

```markdown
# SCHEMA.md - {学科名称}考研知识库宪法

## 一、学科范围
（本学科包含的知识领域）

## 二、页面类型
（本学科的文档类型定义）

## 三、L1 分块原则（学科特色）
（本学科特有的分块规则）

## 四、L3 文档格式（学科特色）
（本学科特有的文档结构）

## 五、学科特有规则
（如：英语的音标格式、政治的引用规范）
```

## 八、维护与管理策略

### 8.1 常规维护

| 频率 | 操作 |
|------|------|
| **每次新增内容后** | 验证 L1→L2→L3 链路完整 |
| **每周** | 运行完整性检查（覆盖率 > 80%） |
| **每月** | 检查重复内容，清理 INDEX.yaml 备份文件 |
| **每季度** | 更新 concept_map.yaml 覆盖新概念 |

### 8.2 冲突检测与处理

**检测方法**：在 INDEX.yaml 中标记 `uncertainty: true` 的条目。

**处理流程**：

```
Step 1：确认冲突内容（对比不同 L1 来源）
Step 2：在 L3 中保留所有原始表述
Step 3：添加"考研建议"小节（基于考纲提供的实践建议）
Step 4：记录冲突日志（{锚点ID}_conflict_log.md）
Step 5：不在 L1 层做任何修改
```

**示例**：
```
某概念在教材A和教材B中有不同定义：
- 教材A：...（一种表述）
- 教材B：...（另一种表述）
- 考研建议：两种表述在考试中均接受，推荐以教材A为主
```

### 8.3 INDEX.yaml 维护规则

| 操作 | 规则 |
|------|------|
| 新增条目 | ✅ 允许，追加到文件末尾 |
| 修改已有条目 | ✅ 允许（只改字段值，不改 anchor ID） |
| 删除条目 | ❌ 禁止（标记 `deprecated: true`） |
| 修改 anchor ID | ❌ 禁止（永久不变） |
| 备份文件 | ⚠️ 定期清理 `INDEX.yaml.bak*` 文件 |

### 8.4 Git 版本管理

知识库使用 Git 进行版本管理：

- ✅ 每次变更提交独立 commit
- ✅ Commit message 格式：`wiki({学科}): {变更描述}`
- ✅ 每次批量更新后打 tag：`wiki-v{日期}`（如 `wiki-v20260513`）
- ❌ 不 rebase 已推送的 wiki 提交（保持历史可追溯）
