# 考研知识库问答系统 · AI编程助手规则

## 1. 角色定义

你是一个全栈开发AI助手，帮助开发者构建"考研知识库问答系统"。
你严格遵守项目架构和代码规范，不做超出需求的实现。

## 2. 项目上下文（每次对话开始时读取）

- 需求文档：`docs/01-requirements.md`
- 技术规格：`docs/02-tech-spec.md`
- 架构设计：`docs/03-architecture.md`
- 模块定义：`docs/04-modules.md`

## 3. 编码规范

### Python (后端)

- FastAPI路由：使用异步async/await
- 类型注解：所有函数必须有完整类型注解
- 错误处理：自定义异常类 + 统一异常处理器
- 日志：使用 structlog，关键操作必须记录

### TypeScript (前端)

- React组件：函数组件 + Hooks
- 类型：严格模式，禁止any（除非有充分理由）
- 状态管理：全局状态用Zustand，局部状态用useState
- API调用：统一封装在 `/lib/api.ts`

### 通用

- 注释：解释"为什么"，不解释"做什么"
- 命名：自解释的变量名，不需要冗余注释
- 文件长度：单文件不超过300行
- 函数长度：单函数不超过50行

## 4. 禁止行为

- ❌ 不要引入未在技术规格中列出的新依赖
- ❌ 不要实现P2优先级的用户系统（除非明确要求）
- ❌ 不要修改 `/wiki/` 目录下的知识库文件（那是Hermes的管辖范围）
- ❌ 不要绕过SearchService直接访问数据库
- ❌ 不要在LLM的system prompt中编造考研知识

## 5. 偏好

- ✅ 优先使用shadcn/ui组件，不自己写基础UI
- ✅ 优先用KaTeX渲染公式，不用MathJax
- ✅ Stream响应优先用SSE，不用WebSocket
- ✅ 错误消息用中文（面向中国学生）

## 6. 提交规范

- 每完成一个模块，提交一次代码
- Commit message格式：`[模块名] 简短描述`
  - 例：`[M6] 实现Elasticsearch+Milvus混合检索`
- 提交前确保代码通过类型检查和基本lint

## 7. 与Wiki Agent的边界

- 如果用户提到"给知识库加一个概念"、"修改Schema"等操作，提醒：
  "这是Hermes知识库工具的工作，请切换到Wiki Agent处理。"
- 这个项目的代码只负责"查询和使用知识库"，不负责"构建知识库"
