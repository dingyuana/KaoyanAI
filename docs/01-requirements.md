# 考研知识库问答系统 · 需求分析文档

## 1. 项目背景

考研学生在复习过程中面临三个痛点：
- 知识点分散在多本教材中，查找效率低
- 无法快速对比不同老师对同一概念的讲解
- 习题和基础知识割裂，难以关联学习

## 2. 用户画像

- **主要用户**：考研学生（数学一/二/三、英语一/二、政治）
- **使用场景**：碎片时间复习、遇到不会的题即时查询、考前系统性回顾
- **技术能力**：不要求技术背景，需要简单直观的界面

## 3. 核心功能需求

### 3.1 知识问答（P0 - 必须实现）

- 用户输入自然语言问题
- 系统基于知识库返回准确答案
- 答案附带引用来源（哪个教材、哪个章节）
- 支持流式输出，减少等待感

### 3.2 学科切换（P0 - 必须实现）

- 用户可以在数学/英语/政治三个学科间切换
- 不同学科使用不同知识库
- UI上清晰标识当前学科

### 3.3 概念浏览（P1 - 重要）

- 以树形结构展示知识库内容
- 用户点击概念名查看详情
- 显示概念间的关联关系

### 3.4 习题关联（P1 - 重要）

- 查询概念时展示相关习题
- 查询习题时展示涉及的概念
- 多解法对比展示

### 3.5 用户系统（P2 - 可选）

- 查询历史记录
- 收藏夹与错题本
- 学习进度追踪

## 4. 非功能需求

### 4.1 性能

- 首次回答时间 < 3秒
- 流式输出首字延迟 < 500ms
- 支持 100 并发用户

### 4.2 准确性

- 数学公式渲染正确率 100%
- 知识库引用来源准确率 100%
- 不编造知识库中没有的内容

### 4.3 可用性

- 移动端适配
- 99.5% 服务可用性
- 友好的错误提示

## 5. 验收标准

- [ ] 用户能在3个学科间自由切换
- [ ] 提问后获得基于知识库的准确回答
- [ ] 回答中所有声明都有知识库来源引用
- [ ] 数学公式正确渲染
- [ ] 10个用户同时使用无明显卡顿
